## ¿Qué es Recon-ng y por qué aprenderlo?

Cuando empiezas en OSINT, usas cada herramienta por separado: theHarvester para emails, subfinder para subdominios, whois para dominios, Shodan para infraestructura. El problema es que los resultados de cada herramienta viven en archivos distintos, en formatos distintos, y cruzar esos datos requiere trabajo manual. Recon-ng resuelve exactamente ese problema.

Recon-ng es un framework de reconocimiento modular escrito en Python que funciona de forma similar a Metasploit: tienes una consola interactiva, cargas módulos especializados, los configuras con opciones, los ejecutas, y los resultados se guardan automáticamente en una base de datos SQLite centralizada. Todos los módulos leen y escriben en esa misma base de datos, lo que significa que el output de un módulo se convierte automáticamente en input del siguiente. Los datos fluyen entre módulos sin intervención manual.

Lo que hace especial a Recon-ng frente a otras herramientas de OSINT es la combinación de tres características que raramente se encuentran juntas:

**Persistencia de datos**: todo lo que encuentras queda guardado en la base de datos del workspace. Si interrumpes el reconocimiento y lo retomas al día siguiente, todos tus hallazgos siguen ahí. Esto es crítico en engagements reales que duran días.

**Modularidad**: hay más de 60 módulos que cubren desde resolución DNS hasta enumeración de LinkedIn, desde búsqueda en Shodan hasta verificación de brechas con HaveIBeenPwned. Cada módulo hace una sola cosa bien.

**Scriptabilidad**: puedes automatizar toda una secuencia de módulos con un script de Recon-ng, lo que permite reproducir el mismo reconocimiento en múltiples objetivos con un solo comando.

## 1. Instalación y primeros pasos

Recon-ng está escrito en Python 3 y se instala con pip. En Kali Linux viene preinstalado, pero conviene tener la versión más reciente porque los módulos se actualizan con frecuencia.

### Instalación

```bash
# En Kali Linux — verificar que está instalado y actualizado
which recon-ng
recon-ng --version

# Actualizar si es necesario
sudo apt update && sudo apt install recon-ng

# En otras distribuciones o para tener la última versión:
pip3 install recon-ng

# Instalación manual desde el repositorio oficial:
git clone https://github.com/lanmaster53/recon-ng.git
cd recon-ng
pip3 install -r REQUIREMENTS
python3 recon-ng

# Para verificar que funciona correctamente después de la instalación:
recon-ng
[recon-ng] > help
```

Cuando abres Recon-ng por primera vez ves una consola similar a Metasploit. El prompt `[recon-ng]` indica que estás en el contexto global. Cuando cargues un módulo, el prompt cambiará a `[recon-ng][nombre_modulo]` para indicar qué módulo está activo.

### Estructura de Recon-ng

Antes de empezar a usarlo es útil entender cómo está organizado internamente:

```
Recon-ng
├── Workspaces          → Proyectos aislados con su propia base de datos
│   ├── default         → Workspace por defecto al iniciar
│   └── [tu_proyecto]   → Workspace que creas para cada engagement
│
├── Módulos             → Las herramientas de reconocimiento
│   ├── recon/          → El núcleo — módulos de reconocimiento
│   ├── discovery/      → Descubrimiento de hosts y servicios
│   ├── exploitation/   → Verificación de vulnerabilidades (limitado)
│   ├── import/         → Importar datos externos al workspace
│   ├── reporting/      → Generar reportes en distintos formatos
│   └── utils/          → Utilidades generales
│
└── Base de datos       → SQLite con tablas para cada tipo de entidad
    ├── domains         → Dominios descubiertos
    ├── hosts           → Hosts con IP y hostname
    ├── contacts        → Personas, emails y teléfonos
    ├── companies       → Organizaciones
    ├── locations       → Geolocalizaciones
    ├── vulnerabilities → Vulnerabilidades encontradas
    └── credentials     → Credenciales identificadas
```

## 2. Workspaces — Proyectos aislados

Lo primero antes de hacer cualquier reconocimiento es crear un workspace dedicado al objetivo. Un workspace en Recon-ng es un proyecto aislado con su propia base de datos SQLite. Así puedes tener múltiples engagements activos en paralelo sin que los datos se mezclen, y retomar cualquier investigación en el punto donde la dejaste.

### Gestión de workspaces

```bash
# Ver todos los workspaces disponibles
[recon-ng] > workspaces list

# Crear un nuevo workspace para el engagement
# El nombre debe ser descriptivo — lo usarás para identificar el proyecto
[recon-ng] > workspaces create example_corp_2025

# Cambiar a un workspace existente
[recon-ng] > workspaces load example_corp_2025

# Confirmar en qué workspace estás actualmente
# El nombre aparece en el prompt entre corchetes
[recon-ng][example_corp_2025] >

# Eliminar un workspace cuando ya no lo necesitas
# CUIDADO: esto borra todos los datos recopilados
[recon-ng] > workspaces remove workspace_viejo
```

Un workspace bien nombrado facilita mucho el trabajo cuando tienes varios proyectos en curso. La convención recomendada es `nombrecliente_año` o `nombrecliente_fechainicio`. Así al listar los workspaces sabes inmediatamente a qué proyecto corresponde cada uno.

### La base de datos del workspace

Cuando creas un workspace, Recon-ng crea automáticamente una base de datos SQLite con varias tablas predefinidas. Cada tabla almacena un tipo de entidad diferente. Esta estructura es lo que permite que los módulos se encadenen: un módulo que encuentra dominios los guarda en la tabla `domains`, y el siguiente módulo que hace resolución DNS lee de esa tabla, procesa cada dominio, y guarda los resultados en `hosts`.

```bash
# Ver todas las tablas disponibles en la base de datos
[recon-ng][example_corp] > db schema

# Output:
# +-------------------+
# |      Tables       |
# +-------------------+
# | domains           |
# | hosts             |
# | contacts          |
# | credentials       |
# | companies         |
# | netblocks         |
# | locations         |
# | ports             |
# | vulnerabilities   |
# | pushpins          |
# | profiles          |
# | leaks             |
# +-------------------+

# Ver el contenido de una tabla
[recon-ng][example_corp] > db query SELECT * FROM domains

# Contar los registros de cada tabla para ver el progreso del reconocimiento
[recon-ng][example_corp] > db query SELECT 'domains' as tabla, COUNT(*) as total FROM domains
[recon-ng][example_corp] > db query SELECT 'hosts' as tabla, COUNT(*) as total FROM hosts
[recon-ng][example_corp] > db query SELECT 'contacts' as tabla, COUNT(*) as total FROM contacts
```

### Insertar datos semilla manualmente

Antes de ejecutar los primeros módulos, necesitas meter en la base de datos el punto de partida: el dominio o dominios objetivo. Esto se hace con `db insert`:

```bash
# Insertar el dominio principal del objetivo
[recon-ng][example_corp] > db insert domains
domain (TEXT): example.com
notes (TEXT):                    # Puedes dejar en blanco con Enter
[*] 1 rows affected.

# Insertar múltiples dominios si el scope incluye varios
[recon-ng][example_corp] > db insert domains
domain (TEXT): example.net

[recon-ng][example_corp] > db insert domains
domain (TEXT): subsidiary-company.com

# Verificar que se han insertado correctamente
[recon-ng][example_corp] > db query SELECT * FROM domains
# +---------------+--------+
# | domain        | notes  |
# +---------------+--------+
# | example.com   | None   |
# | example.net   | None   |
# +---------------+--------+
```

También puedes insertar empresas si el reconocimiento va orientado a encontrar dominios a partir del nombre de la organización:

```bash
[recon-ng][example_corp] > db insert companies
company (TEXT): Example Corp
description (TEXT): Empresa objetivo del engagement
```

## 3. Módulos — La anatomía del framework

Los módulos son el corazón de Recon-ng. Cada módulo implementa una técnica específica de reconocimiento: resolución DNS, búsqueda en Shodan, enumeración de LinkedIn, verificación en HIBP, etc. Entender cómo funcionan y cómo se organizan es la clave para usar el framework de forma efectiva.

### Nomenclatura de módulos

Los módulos siguen una convención de nombres muy descriptiva que indica exactamente qué hace cada uno:

```
recon/[fuente]-[destino]/[nombre_tecnica]

Ejemplos:
recon/domains-hosts/hackertarget
      ↑              ↑
      fuente         destino
      (lee de        (escribe en
      tabla domains) tabla hosts)

recon/domains-contacts/whois_pocs
→ Lee dominios, encuentra contactos vía WHOIS

recon/hosts-ports/shodan
→ Lee hosts, encuentra puertos abiertos vía Shodan

recon/contacts-credentials/hibp
→ Lee contactos (emails), busca credenciales en HIBP
```

Esta convención te dice de un vistazo qué tabla necesita como input y qué tabla va a rellenar como output. Si tienes dominios en la base de datos, buscas módulos que empiecen por `recon/domains-`. Si quieres enriquecer los hosts encontrados, buscas `recon/hosts-`.

### Buscar y explorar módulos

```bash
# Ver todos los módulos disponibles
[recon-ng][example_corp] > modules search

# Filtrar por palabra clave — muy útil para encontrar módulos específicos
[recon-ng][example_corp] > modules search domains
[recon-ng][example_corp] > modules search linkedin
[recon-ng][example_corp] > modules search shodan
[recon-ng][example_corp] > modules search whois
[recon-ng][example_corp] > modules search github

# Ver la descripción completa de un módulo antes de cargarlo
# Muy importante para entender qué hace, qué necesita y qué API keys requiere
[recon-ng][example_corp] > modules info recon/domains-hosts/hackertarget

# Output de info:
#   Name: HackerTarget Lookup
#   Path: modules/recon/domains-hosts/hackertarget.py
#   Author: Tim Tomes (@LaNMaSteR53)
#
#   Description:
#   Uses the hackertarget.com API to find hosts sharing the same
#   IP netblock as the source domain.
#
#   Required Options:
#   SOURCE    (default=default)   source of input
#
#   Required Keys:
#   None (módulo gratuito sin API key)
```

### Instalar módulos del Marketplace

Recon-ng tiene un marketplace donde puedes instalar módulos adicionales. El marketplace contiene módulos de la comunidad que no vienen en la instalación base:

```bash
# Ver todos los módulos disponibles en el marketplace
[recon-ng][example_corp] > marketplace search

# Buscar módulos específicos en el marketplace
[recon-ng][example_corp] > marketplace search linkedin
[recon-ng][example_corp] > marketplace search github

# Instalar un módulo del marketplace
[recon-ng][example_corp] > marketplace install recon/domains-hosts/google

# Ver qué módulos ya tienes instalados
[recon-ng][example_corp] > marketplace search installed

# Actualizar todos los módulos instalados
[recon-ng][example_corp] > marketplace refresh
```

## 4. Configurar y ejecutar módulos

Una vez sabes qué módulo quieres usar, el flujo de trabajo es siempre el mismo: cargar el módulo, revisar sus opciones, configurar lo necesario, y ejecutar. Este flujo es idéntico para todos los módulos, lo que hace que Recon-ng sea muy predecible una vez lo dominas.

### El flujo básico de un módulo

```bash
# 1. Cargar el módulo
[recon-ng][example_corp] > modules load recon/domains-hosts/hackertarget

# El prompt cambia para indicar que el módulo está activo
[recon-ng][example_corp][hackertarget] >

# 2. Ver las opciones del módulo — siempre hacer esto antes de ejecutar
[recon-ng][example_corp][hackertarget] > options list

# Output típico:
# +----------+----------+----------+-----------------------------------------------+
# | Name     | Current  | Required | Description                                   |
# +----------+----------+----------+-----------------------------------------------+
# | SOURCE   | default  | yes      | source of input (see 'info' for details)      |
# +----------+----------+----------+-----------------------------------------------+
#
# SOURCE=default significa que usará todos los dominios de la tabla domains.
# Puedes cambiarlo a un dominio específico si solo quieres procesar uno.

# 3. Ejecutar el módulo con la configuración actual
[recon-ng][example_corp][hackertarget] > run

# 4. Volver al contexto global para cargar el siguiente módulo
[recon-ng][example_corp][hackertarget] > back
```

### La opción SOURCE — cómo controlar el input

La opción `SOURCE` es la más importante de entender porque controla de dónde lee el módulo sus datos de entrada. Tiene tres modos:

```bash
# MODE 1: default — procesa todos los registros de la tabla correspondiente
# Es el comportamiento habitual: usa todos los dominios, todos los hosts, etc.
options set SOURCE default

# MODE 2: un valor específico — procesa solo ese valor
# Útil cuando quieres probar un módulo con un solo objetivo antes de ejecutarlo en masa
options set SOURCE example.com

# MODE 3: una query SQL — selecciona un subconjunto de la tabla
# El más potente: puedes filtrar los registros que quieres procesar
options set SOURCE "SELECT domain FROM domains WHERE domain LIKE '%.com'"
options set SOURCE "SELECT host FROM hosts WHERE host IS NOT NULL LIMIT 10"
```

Esta flexibilidad de SOURCE es lo que permite usar Recon-ng tanto para reconocimiento rápido de un solo objetivo como para campañas masivas que procesan cientos de dominios en serie.

## 5. Módulos esenciales por categoría

Aquí están los módulos más útiles organizados por lo que hacen. Para cada uno explico qué hace exactamente, qué tabla lee, qué tabla escribe, y si necesita API key.

### Enumeración de subdominios y hosts

Estos módulos son los primeros que ejecutamos porque expanden el scope desde los dominios semilla hasta la infraestructura completa.

```bash
# HackerTarget — muy rápido, sin API key, buena cobertura
# Lee: domains | Escribe: hosts
# Consulta la API de hackertarget.com que agrega múltiples fuentes DNS
modules load recon/domains-hosts/hackertarget
run

# BruteForce — fuerza bruta de subdominios con wordlist
# Lee: domains | Escribe: hosts
# Más lento que las fuentes pasivas pero encuentra subdominios únicos
# que no están indexados en ninguna fuente pública
modules load recon/domains-hosts/brute_hosts
options set WORDLIST /usr/share/wordlists/seclists/Discovery/DNS/subdomains-top1million-5000.txt
run

# Google — subdominios indexados por Google
# Lee: domains | Escribe: hosts
# Requiere API key de Google Custom Search
modules load recon/domains-hosts/google_site_web
options set SOURCE example.com
run

# Certificate Transparency via Censys
# Lee: domains | Escribe: hosts
# Encuentra subdominios en los CT logs — muy potente para encontrar entornos ocultos
modules load recon/domains-hosts/censys_subdomains
# Requiere API key de censys.io (gratuita con registro)
run
```

### Resolución y enriquecimiento de hosts

Una vez tenemos una lista de subdominios en la tabla `hosts`, el siguiente paso es resolver sus IPs y enriquecer la información:

```bash
# Resolver IPs de todos los hosts
# Lee: hosts (con hostname) | Escribe: hosts (añade ip_address)
# Este módulo hace resolución DNS de cada hostname y actualiza el registro
modules load recon/hosts-hosts/resolve
run

# Geolocalizar las IPs encontradas
# Lee: hosts (con ip_address) | Escribe: locations + actualiza hosts
# Añade país, ciudad y coordenadas a cada host
modules load recon/hosts-hosts/freegeoip
run

# Shodan — información de servicios y puertos
# Lee: hosts | Escribe: ports + actualiza hosts con información del SO
# Requiere API key de Shodan (gratuita con registro)
modules load recon/hosts-ports/shodan
# Configurar la API key primero:
keys add shodan_api TU_API_KEY_AQUI
run
```

### Información WHOIS y contactos

Estos módulos extraen información de registro de dominios e IPs, que puede revelar personas y emails de contacto:

```bash
# WHOIS de dominios — extrae contactos del registro
# Lee: domains | Escribe: contacts (con nombre, email, teléfono)
# No requiere API key — consulta directamente los servidores WHOIS
modules load recon/domains-contacts/whois_pocs
run

# WHOIS de netblocks — información de los rangos de IPs
# Lee: netblocks | Escribe: contacts
modules load recon/netblocks-contacts/whois_orgs
run

# Resolver hosts a sus netblocks
# Lee: hosts (con ip_address) | Escribe: netblocks
# Identifica a qué organización pertenece cada rango de IPs
modules load recon/hosts-hosts/ip_neighbor
run
```

### Búsqueda de emails y contactos

Encontrar emails corporativos es uno de los objetivos principales del reconocimiento:

```bash
# theHarvester integrado — busca emails en múltiples motores
# Lee: domains | Escribe: contacts (con email)
modules load recon/domains-contacts/harvester
options set SOURCE example.com
run

# PGP Keyserver — emails registrados en servidores de claves PGP
# Lee: domains | Escribe: contacts
# Técnica poco conocida pero efectiva: muchos desarrolladores
# registran su email corporativo en servidores PGP públicos
modules load recon/domains-contacts/pgp_search
run

# EmailHunter (hunter.io)
# Lee: domains | Escribe: contacts
# Requiere API key de hunter.io
modules load recon/domains-contacts/hunter_io
keys add hunter_io TU_API_KEY
run
```

### Verificación de brechas de datos

Uno de los módulos más impactantes en términos de hallazgos:

```bash
# Have I Been Pwned — verificar emails en brechas conocidas
# Lee: contacts (con email) | Escribe: credentials (con breach info)
# Requiere API key de haveibeenpwned.com
modules load recon/contacts-credentials/hibp
keys add hibp_api TU_API_KEY
run

# El resultado añade registros a la tabla credentials con:
# - El email encontrado
# - El nombre de la brecha
# - La fecha de la brecha
# - Qué tipos de datos se expusieron
```

### Enumeración de LinkedIn y redes sociales

LinkedIn es la fuente más rica de inteligencia corporativa:

```bash
# LinkedIn Auth — empleados de una empresa en LinkedIn
# Lee: companies | Escribe: contacts (con nombre y cargo)
# Requiere credenciales de LinkedIn configuradas
modules load recon/companies-contacts/linkedin_auth
# Configurar credenciales:
keys add linkedin_api TU_COOKIE_LI_AT
run

# Twitter — buscar usuarios asociados a una empresa
# Lee: contacts (con nombre) | Escribe: profiles
modules load recon/contacts-profiles/twitter
run

# GitHub — repositorios y usuarios de una organización
# Lee: companies | Escribe: contacts + hosts
# Puede revelar repositorios internos con código fuente y credenciales
modules load recon/companies-multi/github
keys add github_api TU_API_TOKEN
run
```

## 6. Gestionar API keys

Muchos módulos requieren API keys de servicios externos. Recon-ng tiene un sistema centralizado para gestionar estas keys que las almacena de forma segura y las comparte entre todos los módulos del workspace.

### Añadir y gestionar keys

```bash
# Ver todas las API keys configuradas y cuáles faltan
[recon-ng][example_corp] > keys list

# Output muestra:
# +--------------------+-----------------------------------+
# | Name               | Value                             |
# +--------------------+-----------------------------------+
# | shodan_api         | abc123xyz...                      |
# | hunter_io          | def456uvw...                      |
# | hibp_api           | [not set]                         |
# | github_api         | [not set]                         |
# | virustotal_api     | [not set]                         |
# +--------------------+-----------------------------------+

# Añadir una API key
[recon-ng][example_corp] > keys add shodan_api TU_API_KEY_DE_SHODAN

# Actualizar una key existente (mismo comando)
[recon-ng][example_corp] > keys add shodan_api NUEVA_API_KEY

# Eliminar una key
[recon-ng][example_corp] > keys remove shodan_api
```

### Dónde obtener las API keys principales

A continuación las fuentes para cada key, indicando si el plan gratuito es suficiente para reconocimiento básico:

```bash
# Shodan — plan gratuito suficiente para reconocimiento básico

# Limitación gratuita: resultados limitados, sin filtros avanzados

# Hunter.io — plan gratuito: 25 búsquedas al mes

# Have I Been Pwned — requiere pago para consultas por dominio

# Límite: 4 requests/minuto en plan gratuito

# SecurityTrails — plan gratuito: 50 queries al mes
# https://securitytrails.com/app/account/credentials
```

## 7. Flujos completos de reconocimiento

Aquí están los flujos de trabajo completos que uso en engagements reales. Cada flujo está pensado para un objetivo específico y encadena los módulos en el orden óptimo.

### Flujo 1 — Reconocimiento completo de un dominio

Este es el flujo estándar para un engagement típico. Empieza por los módulos gratuitos y sin API key, luego añade los que requieren APIs:

```bash
# 1. Crear workspace y cargar el dominio objetivo
workspaces create example_corp_2025
db insert domains
# domain: example.com

# 2. WHOIS — primero porque puede revelar más dominios relacionados
modules load recon/domains-contacts/whois_pocs
run
back

# 3. Enumeración de subdominios con múltiples fuentes
modules load recon/domains-hosts/hackertarget
run
back

modules load recon/domains-hosts/brute_hosts
options set WORDLIST /usr/share/seclists/Discovery/DNS/subdomains-top1million-5000.txt
run
back

# 4. Resolución DNS — convertir hostnames a IPs
modules load recon/hosts-hosts/resolve
run
back

# 5. Shodan — servicios expuestos en cada IP
modules load recon/hosts-ports/shodan
run
back

# 6. Geolocalización — dónde están los servidores
modules load recon/hosts-hosts/freegeoip
run
back

# 7. Emails y contactos
modules load recon/domains-contacts/harvester
run
back

modules load recon/domains-contacts/pgp_search
run
back

# 8. Verificar emails en brechas de datos
modules load recon/contacts-credentials/hibp
run
back

# 9. Ver el resumen de lo recopilado
db query SELECT COUNT(*) as hosts FROM hosts
db query SELECT COUNT(*) as contacts FROM contacts
db query SELECT COUNT(*) as credentials FROM credentials
db query SELECT * FROM credentials

# 10. Generar reporte
modules load reporting/html
options set FILENAME /tmp/recon_example_corp.html
options set CREATOR "Tu Nombre"
options set CUSTOMER "Example Corp"
run
```

### Flujo 2 — Reconocimiento orientado a phishing

Este flujo está optimizado para obtener una lista de emails válidos y construir un perfil de los empleados clave para una campaña de phishing dirigido:

```bash
# Setup inicial
workspaces create phishing_prep
db insert companies
# company: Example Corp

db insert domains
# domain: example.com

# Enumeración de empleados y emails
modules load recon/domains-contacts/harvester
options set SOURCE example.com
run
back

modules load recon/domains-contacts/hunter_io
run
back

modules load recon/companies-contacts/linkedin_auth
run
back

# Ver los contactos encontrados — buscar nombres, emails y cargos
db query SELECT first_name, last_name, email, title FROM contacts ORDER BY title

# Identificar los objetivos más valiosos
# CTO, CISO, IT Manager, Finance Director = targets prioritarios
db query SELECT first_name, last_name, email, title FROM contacts
  WHERE title LIKE '%director%' OR title LIKE '%manager%' OR title LIKE '%admin%'

# Verificar si algún email está en brechas conocidas
modules load recon/contacts-credentials/hibp
run
back

# Exportar lista de emails para campañas
db query SELECT email FROM contacts WHERE email IS NOT NULL
```

### Flujo 3 — Reconocimiento de infraestructura AWS/Cloud

Muchas empresas tienen su infraestructura en cloud. Este flujo está orientado a mapear activos cloud:

```bash
workspaces create infra_cloud
db insert domains
# domain: example.com

# 1. Buscar subdominios que apunten a cloud providers
modules load recon/domains-hosts/hackertarget
run
back

modules load recon/hosts-hosts/resolve
run
back

# 2. Identificar proveedores cloud por los rangos de IP
# Las IPs de AWS, Azure y GCP tienen rangos conocidos
modules load recon/hosts-hosts/ipinfodb
run
back

# Consultar qué IPs están en rangos de AWS
# Los rangos de AWS empiezan típicamente por 3.x.x.x, 18.x.x.x, 52.x.x.x, etc.
db query SELECT host, ip_address FROM hosts
  WHERE ip_address LIKE '3.%' OR ip_address LIKE '18.%' OR ip_address LIKE '52.%'
```

## 8. Consultas SQL avanzadas a la base de datos

La base de datos SQLite de Recon-ng es un activo en sí mismo. Saber hacer consultas SQL te permite extraer exactamente la información que necesitas en el formato que necesitas, sin depender solo de los comandos predefinidos.

### Consultas útiles para análisis

```sql
-- Ver todos los hosts con su IP y el módulo que los descubrió
db query SELECT host, ip_address, module FROM hosts ORDER BY host

-- Encontrar hosts sin IP (resolución DNS fallida — pueden ser interesantes)
db query SELECT host FROM hosts WHERE ip_address IS NULL

-- Contar hosts por dominio principal
db query SELECT SUBSTR(host, INSTR(host, '.') + 1) as domain, COUNT(*) as count
         FROM hosts GROUP BY domain ORDER BY count DESC

-- Ver todos los emails encontrados con su fuente
db query SELECT email, title, module FROM contacts WHERE email IS NOT NULL ORDER BY email

-- Buscar emails de dominios específicos
db query SELECT email FROM contacts WHERE email LIKE '%@example.com'

-- Ver credenciales encontradas con detalle de la brecha
db query SELECT username, password, hash, leak_id FROM credentials

-- Cruzar contactos con credenciales (empleados con datos en brechas)
db query SELECT c.email, c.title, cr.leak_id
         FROM contacts c
         JOIN credentials cr ON c.email = cr.username
         WHERE c.email IS NOT NULL

-- Ordenar hosts por número de puertos abiertos (los más expuestos primero)
db query SELECT h.host, h.ip_address, COUNT(p.port) as open_ports
         FROM hosts h LEFT JOIN ports p ON h.ip_address = p.ip_address
         GROUP BY h.host ORDER BY open_ports DESC

-- Ver puertos abiertos agrupados
db query SELECT port, protocol, COUNT(*) as hosts
         FROM ports GROUP BY port, protocol ORDER BY hosts DESC

-- Exportar datos a CSV directamente
db query SELECT host, ip_address, region, country FROM hosts WHERE ip_address IS NOT NULL
```

### Importar datos externos

Recon-ng también puede importar datos generados por otras herramientas, lo que permite centralizar todos los hallazgos:

```bash
# Importar hosts desde un archivo de texto (uno por línea)
modules load import/list
options set FILENAME /tmp/subdominios_de_subfinder.txt
options set TABLE hosts
options set COLUMN host
run

# Importar desde nmap XML
modules load import/nmap
options set FILENAME /tmp/nmap_scan.xml
run

# Importar desde Metasploit
# Exportar primero desde msfconsole: db_export -f xml /tmp/msf_export.xml
modules load import/metasploit
options set FILENAME /tmp/msf_export.xml
run
```

## 9. Generación de reportes

Cuando el reconocimiento está completo, necesitas presentar los hallazgos de forma profesional. Recon-ng incluye módulos de reporting que generan el reporte directamente desde la base de datos.

### Reporte HTML — El más completo

El reporte HTML genera una página web navegable con todas las tablas de la base de datos, imágenes de geolocalización y un resumen ejecutivo. Es el formato recomendado para presentar al cliente o al equipo.

```bash
[recon-ng][example_corp] > modules load reporting/html
```

## 10. Automatización con scripts

Una de las funcionalidades más potentes de Recon-ng es la capacidad de ejecutar secuencias de comandos desde un archivo, lo que permite reproducir el mismo reconocimiento en múltiples objetivos de forma automatizada.

### Crear un script de reconocimiento

Un script de Recon-ng es simplemente un archivo de texto con comandos, uno por línea. Puedes guardar tu flujo de trabajo en un script y reutilizarlo:

```bash
# Crear el archivo de script
cat > /home/user/recon_scripts/full_recon.rc << 'SCRIPT'
# Script de reconocimiento completo para Recon-ng
# Uso: recon-ng -w WORKSPACE -r full_recon.rc

# Cargar módulos de enumeración de subdominios
modules load recon/domains-hosts/hackertarget
run
back

modules load recon/domains-hosts/brute_hosts
options set WORDLIST /usr/share/seclists/Discovery/DNS/subdomains-top1million-5000.txt
run
back

# Resolución DNS
modules load recon/hosts-hosts/resolve
run
back

# Enumeración de contactos
modules load recon/domains-contacts/whois_pocs
run
back

modules load recon/domains-contacts/harvester
run
back

# Verificación de brechas
modules load recon/contacts-credentials/hibp
run
back

# Generar reporte HTML
modules load reporting/html
options set CREATOR "Red Team"
options set CUSTOMER "Objetivo"
options set FILENAME /tmp/recon_report.html
run

# Salir cuando termine
exit
SCRIPT
```

### Ejecutar el script

```bash
# Crear workspace, insertar dominio y ejecutar el script
recon-ng -w example_corp -r /home/user/recon_scripts/full_recon.rc

# También puedes pasar comandos directamente sin abrir la consola interactiva
# Útil para integrar Recon-ng en pipelines de CI/CD o scripts de bash
recon-ng -w example_corp -C "db insert domains; db query INSERT INTO domains (domain) VALUES ('example.com')"
```

### Script bash que automatiza todo el proceso

Este script crea el workspace, inserta el dominio, ejecuta el reconocimiento completo y recoge los resultados:

```bash
#!/bin/bash
# recon_ng_auto.sh — Automatización completa de Recon-ng
# Uso: ./recon_ng_auto.sh example.com

TARGET=$1
WORKSPACE="${TARGET//./_}_$(date +%Y%m%d)"
REPORT_DIR="./reports/${WORKSPACE}"
SCRIPT_FILE="/tmp/recon_script_${WORKSPACE}.rc"

if [ -z "$TARGET" ]; then
    echo "[-] Uso: $0 <dominio>"
    exit 1
fi

mkdir -p "$REPORT_DIR"

echo "[*] Objetivo: $TARGET"
echo "[*] Workspace: $WORKSPACE"
echo "[*] Generando script de reconocimiento..."

# Generar el script de Recon-ng dinámicamente
cat > "$SCRIPT_FILE" << RECONSCRIPT
db insert domains
${TARGET}

modules load recon/domains-hosts/hackertarget
run
back

modules load recon/hosts-hosts/resolve
run
back

modules load recon/domains-contacts/whois_pocs
run
back

modules load recon/domains-contacts/harvester
run
back

modules load reporting/html
options set CREATOR "Red Team"
options set CUSTOMER ${TARGET}
options set FILENAME ${REPORT_DIR}/report.html
run

exit
RECONSCRIPT

echo "[*] Ejecutando Recon-ng..."
recon-ng -w "$WORKSPACE" -r "$SCRIPT_FILE"

echo "[+] Reconocimiento completado"
echo "[+] Reporte: ${REPORT_DIR}/report.html"
echo ""
echo "[*] Estadísticas:"
# Acceder directamente a la base de datos SQLite para mostrar estadísticas
DBPATH="${HOME}/.recon-ng/workspaces/${WORKSPACE}/data.db"
if [ -f "$DBPATH" ]; then
    sqlite3 "$DBPATH" "SELECT 'Hosts: ' || COUNT(*) FROM hosts;"
    sqlite3 "$DBPATH" "SELECT 'Contactos: ' || COUNT(*) FROM contacts;"
    sqlite3 "$DBPATH" "SELECT 'Credenciales en brechas: ' || COUNT(*) FROM credentials;"
fi

# Limpiar script temporal
rm -f "$SCRIPT_FILE"
```
