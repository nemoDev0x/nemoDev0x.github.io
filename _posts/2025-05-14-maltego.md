## ¿Qué es Maltego y por qué lo usan los profesionales?

La mayoría de las herramientas de OSINT te devuelven listas: una lista de subdominios, una lista de emails, una lista de IPs. Maltego hace algo diferente y mucho más potente — te devuelve un **grafo de relaciones**. En lugar de decirte "estos son los emails de la empresa", Maltego te muestra visualmente cómo ese email está conectado con una persona, esa persona con una empresa, esa empresa con un dominio, ese dominio con tres IPs, esas IPs con certificados SSL que a su vez revelan más dominios. Todo en una interfaz gráfica que puedes explorar como si fuese un mapa.

Esto cambia fundamentalmente cómo se hace el reconocimiento. Cuando tienes 200 datos en una lista, encontrar conexiones entre ellos requiere horas de análisis manual. Cuando los tienes en un grafo, las conexiones son visibles de inmediato. Un nodo conectado a muchos otros es un activo crítico. Un email que aparece en tres organizaciones distintas puede ser una persona con múltiples afiliaciones. Un dominio que comparte infraestructura con otro puede revelar que pertenecen al mismo grupo corporativo.

Maltego se usa en tres disciplinas principalmente:

- **Pentesting y Red Team**: para mapear la superficie de ataque de un objetivo antes de la fase activa
- **Threat Intelligence**: para rastrear actores maliciosos, infraestructura de malware y grupos APT
- **Investigación periodística y forense**: para descubrir relaciones entre personas, empresas y activos

La herramienta fue creada por la empresa sudafricana Paterva y actualmente la distribuye Maltego Technologies. Existe en versión **Community** (gratuita, con limitaciones) y en versiones de pago **Professional** y **Enterprise**.

## 1. El modelo conceptual: entidades y transforms

Antes de instalar nada, es fundamental entender cómo piensa Maltego. Toda la lógica de la herramienta se basa en dos conceptos: **entidades** y **transforms**.

### Entidades — los nodos del grafo

Una entidad es cualquier objeto de inteligencia: una persona, un dominio, un email, una IP, una organización, un número de teléfono, un alias en redes sociales, una wallet de Bitcoin, un hash de malware. Cada entidad se representa como un nodo en el grafo y tiene propiedades asociadas.

Las entidades predefinidas que vienen con Maltego cubren los objetos más comunes en OSINT:

```
Infraestructura:
├── Domain          → example.com
├── DNS Name        → mail.example.com
├── IP Address      → 93.184.216.34
├── Netblock        → 93.184.216.0/24
├── AS (Autonomous System) → AS15169
└── URL             → https://example.com/login

Identidad:
├── Person          → John Smith
├── Email Address   → jsmith@example.com
├── Phone Number    → +34 91 123 4567
├── Alias           → @jsmith_hacker
└── Twitter Affiliation → @example_corp

Organización:
├── Organization    → Example Corp
├── Website         → https://www.example.com
└── Affiliation     → "works at Example Corp"

Archivos:
├── Document        → informe_anual.pdf
├── Image           → logo.png
└── Hash            → d41d8cd98f00b204e9800998ecf8427e
```

Cada entidad tiene campos internos que almacenan sus propiedades. Por ejemplo, la entidad "Domain" tiene el campo `fqdn` con el nombre del dominio, y además campos para el registrante, las fechas, los name servers, etc. Estos campos se rellenan automáticamente cuando ejecutas transforms.

### Transforms — las aristas que conectan los nodos

Un transform es una función que toma una entidad como entrada, consulta alguna fuente de datos (DNS, WHOIS, Shodan, VirusTotal, LinkedIn, etc.) y devuelve nuevas entidades como resultado. Esas nuevas entidades se añaden al grafo con una arista que las conecta a la entidad original.

Por ejemplo:

```
Domain [example.com]
    │
    ├── "DNS - Get MX records"        → Email Server [mail.example.com]
    ├── "DNS - Get NS records"        → DNS Name [ns1.example.com]
    ├── "To IP Address [DNS]"         → IP Address [93.184.216.34]
    ├── "WHOIS - Get Registrant"      → Person [John Smith]
    └── "Get Subdomains [crt.sh]"     → DNS Name [dev.example.com]
                                         DNS Name [staging.example.com]
                                         DNS Name [admin.example.com]
```

Cada nodo del grafo puede a su vez ser input de más transforms. Desde `IP Address [93.184.216.34]` puedes ejecutar:

```
IP Address [93.184.216.34]
    │
    ├── "To Netblock [WHOIS]"         → Netblock [93.184.216.0/24]
    ├── "To AS [WHOIS]"               → AS [AS15169 - Google LLC]
    ├── "Shodan - Get Open Ports"     → Ports [22, 80, 443, 8080]
    └── "To Domain [Reverse DNS]"     → Domain [example.com]
```

Esta capacidad de encadenar transforms indefinidamente es lo que hace que Maltego sea tan potente. Puedes partir de un solo dominio y en 20 minutos tener un grafo con 300 nodos que muestra toda la infraestructura de una empresa.

## 2. Instalación y configuración inicial

Maltego está disponible para Windows, macOS y Linux. Requiere Java 11 o superior, que en la mayoría de sistemas ya está instalado.

### Descarga e instalación

```bash
# En Kali Linux, Maltego viene preinstalado.
# Para verificar que está disponible:
which maltego
maltego --version

# Si no está instalado en Kali:
sudo apt update
sudo apt install maltego

# En otras distribuciones Linux, descargar desde la web oficial:
# https://www.maltego.com/downloads/
# Descomprimir y ejecutar el binario:
chmod +x maltego_linux_v4.x.x.sh
./maltego_linux_v4.x.x.sh

# En macOS con Homebrew:
brew install --cask maltego
```

### Primer lanzamiento y registro

La primera vez que abres Maltego te pide elegir el tipo de licencia. Para la **Community Edition** (gratuita):

1. Seleccionar "Maltego CE (Free)" en la pantalla de inicio
2. Hacer clic en "Register Here" para crear una cuenta en maltego.com
3. Confirmar el email que recibirás
4. Volver a Maltego e introducir las credenciales

Para la mayoría de prácticas de aprendizaje y CTFs, la Community Edition es suficiente. Para engagements reales de Red Team necesitarás la licencia Professional.

## 3. Instalar y gestionar transforms

Los transforms son el corazón de Maltego. Los que vienen por defecto cubren DNS, WHOIS y algunas búsquedas básicas. Para sacarle todo el partido necesitas instalar Transform Hubs adicionales.

### Transform Hub

El Transform Hub es la tienda de transforms de Maltego. Se accede desde el menú `Transforms → Transform Hub`. Desde aquí puedes instalar paquetes de transforms organizados por categoría o proveedor.

Los más útiles para OSINT son:

**Gratuitos:**

```
Shodan                → Buscar hosts, puertos y banners en Shodan
VirusTotal            → Análisis de dominios, IPs, URLs y hashes
Have I Been Pwned     → Verificar emails en brechas de datos
BuiltWith             → Tecnologías usadas por un sitio web
Censys                → Búsqueda de hosts y certificados
DNS                   → Resolución y enumeración DNS completa
WHOIS XML API         → Datos WHOIS extendidos
Social Links CE       → Búsqueda en redes sociales (versión gratuita)
```

**De pago o con API key:**

```
Recorded Future       → Threat intelligence avanzada
PassiveTotal (RiskIQ) → DNS pasivo e infraestructura de amenazas
Maltego Clearbit      → Datos de empresas y contactos
Full Contact          → Enriquecimiento de perfiles de personas
```

Para instalar un Transform Hub:

```
1. Ir a Transforms → Transform Hub
2. Localizar el hub deseado (ej: "Shodan")
3. Hacer clic en "Install"
4. Si requiere API key, introducirla cuando se solicite
5. Los nuevos transforms aparecerán en el menú contextual
```

### Configurar API keys

Muchos transforms requieren API keys de servicios externos. Estas keys se configuran en:

```
Transforms → Transform Manager → (seleccionar transform) → Settings
```

API keys esenciales que deberías tener configuradas:

```bash
# Shodan — gratuita con registro en shodan.io
# Plan gratuito: búsquedas limitadas, sin filtros avanzados
# https://account.shodan.io

# VirusTotal — gratuita con registro en virustotal.com
# Límite: 4 requests/minuto en plan gratuito
# https://www.virustotal.com/gui/my-apikey

# Have I Been Pwned — requiere plan de pago para dominio completo
# https://haveibeenpwned.com/API/Key

# SecurityTrails — plan gratuito con 50 queries/mes
# https://securitytrails.com/app/account/credentials
```

## 4. Flujo básico: investigar un dominio desde cero

Vamos a hacer un reconocimiento completo de un dominio paso a paso, explicando qué hace cada transform y por qué lo ejecutamos en ese orden.

### Paso 1 — Crear un nuevo grafo

```
File → New → Blank Graph
```

Dale un nombre descriptivo al grafo, por ejemplo "Recon_ExampleCorp_2025". Maltego guarda los grafos como archivos `.mtgx` que puedes reabrir, compartir con el equipo, o exportar a imagen.

### Paso 2 — Añadir la entidad inicial

En el panel izquierdo busca la entidad "Domain" y arrástrala al área del grafo. Haz doble clic en ella para editar sus propiedades y escribe el dominio objetivo: `example.com`.

Esta es la semilla de todo el reconocimiento. Desde este único nodo vamos a expandir el grafo progresivamente.

### Paso 3 — Ejecutar transforms DNS básicos

Haz clic derecho sobre el nodo `example.com` para ver el menú contextual con todos los transforms disponibles. Los primeros que ejecutamos son siempre los de DNS porque son gratuitos, no dejan rastro, y revelan la infraestructura básica inmediatamente.

```
Clic derecho en [example.com] → Run Transform → DNS from Domain:
├── "DNS - Get MX records"        → Servidores de correo
├── "DNS - Get NS records"        → Name servers
├── "DNS - Get SOA records"       → Información de zona DNS
├── "DNS - Get TXT records"       → Registros SPF, DKIM, DMARC, verificaciones
└── "To IP Address [DNS]"         → IP del servidor web principal
```

**Por qué importa cada uno:**

- **MX records**: revelan el proveedor de email (Google Workspace, Microsoft 365, servidor propio). Si usan servidores propios, el MX suele tener una IP directa interesante.
- **NS records**: muestran quién gestiona el DNS. Si son name servers propios (ej: `ns1.example.com`) es una IP más a escanear.
- **TXT records**: el registro SPF indica qué servidores están autorizados a enviar email en nombre del dominio, revelando proveedores de servicios (Salesforce, Mailchimp, SendGrid, etc.). El DMARC muestra la política de seguridad del email.
- **IP principal**: la IP a la que apunta el dominio. Puede estar detrás de Cloudflare, en cuyo caso obtendrás la IP del CDN, no la real.

Después de ejecutar estos transforms, el grafo ya tiene varios nodos nuevos conectados al dominio original.

### Paso 4 — Expandir desde las IPs

Haz clic derecho en cada IP encontrada y ejecuta:

```
Clic derecho en [93.184.216.34] → Run Transform:
├── "To Netblock [WHOIS]"         → Bloque de IPs al que pertenece
├── "To AS [WHOIS]"               → Autonomous System (quién es el proveedor)
├── "To Domain [Reverse DNS]"     → Otros dominios alojados en esa IP
└── "Shodan - Get Open Ports"     → Puertos y servicios abiertos (si tienes Shodan)
```

El transform "To Domain [Reverse DNS]" es especialmente interesante porque puede revelar otros dominios alojados en el mismo servidor. Si una empresa tiene varios dominios en la misma IP, probablemente están relacionados corporativamente.

El transform de Shodan directamente desde Maltego añade nodos de tipo "Port" conectados a la IP, mostrando visualmente qué servicios expone ese servidor. Puedes ver de un vistazo si tiene RDP abierto, SSH, un panel web, etc.

### Paso 5 — WHOIS e información de registro

```
Clic derecho en [example.com] → Run Transform → WHOIS:
├── "WHOIS - Get Registrant"       → Persona o empresa que registró el dominio
├── "WHOIS - Get Admin Contact"    → Contacto administrativo
└── "WHOIS - Get Technical Contact" → Contacto técnico (a veces distinto)
```

Si los datos WHOIS no están protegidos por privacidad, aparecerán nodos de tipo "Person" o "Email Address" conectados al dominio. Esos emails son potenciales targets para phishing o para verificar en bases de datos de brechas.

### Paso 6 — Subdominios y certificados

```
Clic derecho en [example.com] → Run Transform → DNS:
├── "Get Subdomains [crt.sh]"      → Subdominios de Certificate Transparency
├── "To DNS Name [Brute Force]"    → Fuerza bruta de subdominios (semi-activo)
└── "Get DNS Names from Website"   → Subdominios mencionados en la web principal
```

El transform de crt.sh es completamente pasivo y muy potente. En la Community Edition devuelve hasta 12 resultados, pero los ordenará por relevancia. Cada subdominio aparece como un nuevo nodo DNS conectado al dominio principal.

Desde cada subdominio puedes a su vez resolver su IP y expandir más el grafo.

## 5. Investigar una persona — Person OSINT

Cuando en la fase de reconocimiento encontramos nombres de empleados (vía LinkedIn, WHOIS, documentos, etc.), podemos crear nodos de tipo "Person" en Maltego y expandirlos para construir un perfil completo.

### Crear una entidad Person

Arrastra la entidad "Person" al grafo y rellena sus propiedades:
- `Full Name`: John Smith
- `First Name`: John
- `Last Name`: Smith

### Transforms sobre Person

```
Clic derecho en [John Smith] → Run Transform:
├── "Person to Email [Pattern]"    → Genera posibles emails según patrones
├── "Search Twitter"               → Busca la persona en Twitter/X
├── "Search LinkedIn"              → Perfil en LinkedIn (requiere configuración)
├── "To Website [Search Engine]"   → Busca la persona en Google
└── "Phone to Person [Full Contact]" → Enriquecimiento de datos (requiere API)
```

### El nodo Email como pivote

Una vez tienes un email, ya sea de WHOIS, LinkedIn o theHarvester, ese email se convierte en uno de los pivotes más valiosos del grafo:

```
Clic derecho en [jsmith@example.com] → Run Transform:
├── "Email to Person"              → Infiere el nombre real
├── "Have I Been Pwned"            → Brechas donde apareció este email
├── "To Domain [Extract Domain]"   → Extrae example.com del email
├── "Gravatar"                     → Foto de perfil asociada al email
└── "Search Social Networks"       → Presencia en redes sociales
```

El transform de Have I Been Pwned es especialmente útil: si el email aparece en brechas, el nodo se conectará a nodos de tipo "Breach" que muestran en qué brecha apareció, cuándo fue, y qué tipo de datos se filtraron. Si la brecha incluía contraseñas, ese email pasa inmediatamente a la lista de objetivos prioritarios para probar acceso.

## 6. Investigar infraestructura — IP y Netblock OSINT

Cuando una empresa tiene un rango de IPs propio (un ASN propio o un netblock asignado por su ISP), investigar ese rango puede revelar docenas de servicios que no están documentados en ningún DNS público.

### Partir de un netblock

Si has identificado que la empresa usa el rango `93.184.216.0/24`, puedes empezar desde ahí:

```
Arrastra entidad "Netblock" → introduce 93.184.216.0/24

Clic derecho en [93.184.216.0/24] → Run Transform:
├── "Netblock to IP Addresses"     → Lista todas las IPs del rango (hasta 12 en CE)
├── "To AS [WHOIS]"                → Autonomous System del bloque
└── "Shodan - Port Scan Netblock"  → Servicios abiertos en el rango (Shodan)
```

Desde cada IP generada puedes continuar expandiendo:

```
Clic derecho en [93.184.216.50] → Run Transform:
├── "To Domains [Reverse DNS]"     → Dominios alojados en esa IP
├── "Shodan - Get Open Ports"      → Servicios expuestos
└── "To SSL Certificate"           → Certificados SSL instalados
```

Los certificados SSL son especialmente reveladores porque pueden mostrar Subject Alternative Names (SANs) — dominios adicionales incluidos en el mismo certificado. Así encuentras dominios internos o de test que nunca aparecerían en un DNS público.

### Investigar un Autonomous System

El número AS identifica a una organización en el sistema de enrutamiento de internet. Grandes empresas tienen su propio AS con múltiples rangos de IPs.

```
Arrastra entidad "AS" → introduce AS15169 (Google) o el número del objetivo

Clic derecho en [AS15169] → Run Transform:
├── "AS to Netblocks [RADB]"       → Todos los rangos IP del AS
├── "AS to Organization"           → Nombre de la organización
└── "AS to Country"                → País de registro
```

Esto puede revelar que una empresa tiene rangos de IPs en múltiples países o regiones, información que no es evidente buscando solo el dominio principal.

## 7. Casos de uso avanzados en Red Team

### Caso 1 — Mapear la cadena de suministro

Un vector de ataque frecuente en Red Team avanzado es comprometer a un proveedor de la empresa objetivo en lugar de atacarla directamente. Las defensas del proveedor suelen ser más débiles, y si tiene acceso VPN o APIs conectadas al objetivo, ese acceso puede ser el camino de entrada.

Para mapear la cadena de suministro en Maltego:

```
[example.com] → "Get Technology [BuiltWith]" → [Salesforce] [AWS] [Cloudflare] [Intercom]

# Desde cada proveedor detectado:
[Salesforce] → "To Domain" → [salesforce.com]
             → "To IP Range" → rangos de Salesforce que se conectan a la empresa

# También desde las ofertas de trabajo (manual):
# Si la empresa busca "Salesforce admin", tienen Salesforce
# Si buscan "AWS Solutions Architect", tienen AWS
```

Con BuiltWith instalado, el transform "Get Technologies from Domain" devuelve automáticamente todos los servicios de terceros que usa el sitio web: CDN, analytics, chat en vivo, CRM, plataforma de email marketing, etc. Cada uno de esos servicios es una tercera parte con acceso a datos de la empresa.

### Caso 2 — Rastrear infraestructura de phishing

Cuando recibes un email de phishing o detectas un dominio malicioso que imita a tu empresa, Maltego es ideal para rastrear toda la infraestructura del atacante.

```
[dominio-phishing.com] → IP → Netblock → otros dominios en esa IP
                       → WHOIS → email del registrante
                       → email → otros dominios registrados con ese email
                       → SSL cert → SANs → más dominios del atacante
```

Este proceso de "pivoting" desde un indicador inicial te permite descubrir toda la infraestructura de una campaña de phishing en minutos. Si el atacante reutiliza la misma IP o el mismo email de registro para varios dominios maliciosos, Maltego te lo muestra inmediatamente como un nodo conectado a múltiples aristas.

### Caso 3 — Correlacionar brechas de datos con activos

```
[example.com] → WHOIS emails → HIBP → brechas
             → theHarvester emails → HIBP → brechas
             → LinkedIn employees → generar emails → HIBP → brechas
```

Al final de este flujo tienes un subgrafo que muestra exactamente qué empleados tienen credenciales comprometidas en brechas conocidas. Si alguno tiene privilegios elevados (CISO, sysadmin, CTO), ese email se convierte en objetivo prioritario para probar acceso en servicios corporativos expuestos como OWA o VPN.

## 8. Gestionar grafos grandes — técnicas de organización

Cuando el grafo crece a cientos de nodos, la visualización se vuelve caótica. Maltego tiene herramientas para gestionar esto.

### Layouts disponibles

```
View → Layouts:
├── Organic          → Distribución por fuerza, muestra clusters naturales
├── Hierarchical     → Árbol de arriba abajo, bueno para dominios/subdominios
├── Block            → Grid ordenado, útil para listas de IPs
├── Circular         → Todos los nodos en círculo alrededor del central
└── Edge Weighted    → Los nodos más conectados quedan al centro
```

El layout **Organic** es el que más información visual da porque agrupa automáticamente los nodos que están muy conectados entre sí. Si hay un cluster de IPs que comparten el mismo netblock aparecerán juntas. Si hay un email conectado a muchas brechas será visible de inmediato.

### Filtrar y ocultar nodos

Cuando el grafo tiene 300 nodos y quieres centrarte en las IPs, puedes ocultar temporalmente el resto:

```
Seleccionar todos los nodos de un tipo:
Edit → Select → Select Entities of Same Type

Ocultar selección:
View → Hide Selected

# Para ver solo los nodos de tipo IP Address:
1. Clic en cualquier IP
2. Edit → Select → Select Entities of Same Type
3. View → Focus on Selection
```

### Usar Machine Learning para detectar patrones

La versión Professional incluye funciones de ML que detectan automáticamente clusters y anomalías en el grafo. En la versión Community puedes hacer algo similar manualmente: busca nodos con muchas conexiones (indicadores de activos críticos) o nodos que conectan clusters separados (posibles pivots).

## 10. Maltego con API propia — Crear transforms personalizados

Cuando las fuentes de datos que necesitas no están en el Transform Hub, puedes crear tus propios transforms. Un transform personalizado es básicamente un script (Python, PHP, etc.) que recibe una entidad como input, consulta una fuente de datos, y devuelve nuevas entidades en formato XML.

### Estructura de un transform personalizado en Python

```python
#!/usr/bin/env python3
"""
Transform personalizado para Maltego.
Toma un dominio y devuelve sus subdominios usando la API de crt.sh.
"""

import sys
import requests
import json

def get_subdomains_crtsh(domain):
    """Consulta crt.sh y devuelve subdominios del dominio objetivo."""
    url = f"https://crt.sh/?q=%.{domain}&output=json"
    try:
        response = requests.get(url, timeout=10)
        data = response.json()
    except Exception as e:
        return []

    subdomains = set()
    for cert in data:
        # name_value puede contener múltiples dominios separados por newlines
        for name in cert['name_value'].split('\n'):
            name = name.strip().lstrip('*.')
            # Solo nos quedamos con subdominios del dominio objetivo
            if domain in name and name != domain:
                subdomains.add(name)

    return list(subdomains)

def domain_to_maltego_xml(domain, subdomains):
    """
    Genera el XML que Maltego espera recibir como respuesta del transform.
    Cada entidad se define con su tipo y valor principal.
    """
    xml_output = '<?xml version="1.0" encoding="UTF-8"?>\n'
    xml_output += '<MaltegoMessage>\n'
    xml_output += '  <MaltegoTransformResponseMessage>\n'
    xml_output += '    <Entities>\n'

    for subdomain in subdomains:
        xml_output += f'''      <Entity Type="maltego.DNSName">
        <Value>{subdomain}</Value>
        <Weight>100</Weight>
        <AdditionalFields>
          <Field Name="fqdn">{subdomain}</Field>
        </AdditionalFields>
      </Entity>\n'''

    xml_output += '    </Entities>\n'
    xml_output += '  </MaltegoTransformResponseMessage>\n'
    xml_output += '</MaltegoMessage>'

    return xml_output

if __name__ == '__main__':
    # Maltego pasa el valor de la entidad como primer argumento
    if len(sys.argv) < 2:
        print("Uso: python3 transform.py <dominio>")
        sys.exit(1)

    domain = sys.argv[1]
    subdomains = get_subdomains_crtsh(domain)

    print(domain_to_maltego_xml(domain, subdomains))
```

## 11. Alternativas a Maltego y cuándo usarlas

Maltego no siempre es la herramienta correcta. Estas son las alternativas y cuándo tiene sentido usarlas:

### SpiderFoot — Cuando quieres automatización total

SpiderFoot automatiza el mismo tipo de reconocimiento que Maltego pero sin interfaz gráfica de grafo. Es más rápido y puede ejecutarse como servidor web o desde CLI. La ventaja es que no requiere ejecutar transforms manualmente: configuras el objetivo, eliges los módulos, y SpiderFoot hace todo solo.

```bash
# Instalación
pip3 install spiderfoot

# Iniciar servidor web
python3 sf.py -l 127.0.0.1:5001

# Desde navegador: http://127.0.0.1:5001
# Crear nuevo scan → introducir dominio → seleccionar módulos → ejecutar
```

**Cuándo usar SpiderFoot en lugar de Maltego**: cuando quieres hacer un reconocimiento rápido y amplio sin intervención manual, o cuando necesitas ejecutar el reconocimiento en un servidor sin interfaz gráfica.

### Recon-ng — Cuando quieres CLI y modularidad

Recon-ng tiene una interfaz similar a Metasploit: módulos que se cargan y ejecutan uno a uno. Los resultados se almacenan en una base de datos SQLite y se pueden exportar. No tiene visualización gráfica pero es muy preciso y scriptable.

```bash
recon-ng
[recon-ng] > workspaces create example_corp
[recon-ng] > modules load recon/domains-hosts/hackertarget
[recon-ng][hackertarget] > options set SOURCE example.com
[recon-ng][hackertarget] > run
```

**Cuándo usar Recon-ng**: cuando prefieres CLI, cuando necesitas integrar el reconocimiento en un pipeline automatizado, o cuando trabajas en un servidor remoto por SSH.

### Cuándo usar Maltego

Maltego brilla en tres situaciones concretas:

1. **Cuando necesitas encontrar conexiones no obvias** entre entidades de diferentes tipos. El grafo visual hace evidente lo que en una tabla sería invisible.
2. **Cuando investigas a una persona o actor de amenaza** y necesitas construir un perfil completo cruzando múltiples fuentes.
3. **Cuando presentas resultados a un cliente o equipo** — un grafo visual de relaciones es infinitamente más impactante que una lista de IPs en un CSV.

── TRANSFORMS ESENCIALES POR ENTIDAD ────────────────────────
Domain:
  → "To IP Address [DNS]"          → IP del servidor
  → "Get Subdomains [crt.sh]"      → Subdominios vía CT logs
  → "DNS - Get MX records"         → Servidor de correo
  → "DNS - Get TXT records"        → SPF, DKIM, DMARC
  → "WHOIS - Get Registrant"       → Datos de registro

IP Address:
  → "To Netblock [WHOIS]"          → Rango al que pertenece
  → "To AS [WHOIS]"                → Autonomous System
  → "To Domain [Reverse DNS]"      → Otros dominios en esa IP
  → "Shodan - Get Open Ports"      → Servicios expuestos

Email Address:
  → "Have I Been Pwned"            → Brechas donde apareció
  → "To Person [Gravatar]"         → Foto asociada al email
  → "To Domain [Extract Domain]"   → Dominio del email

Person:
  → "Person to Email [Pattern]"    → Posibles emails
  → "Search Social Networks"       → Presencia en redes
  → "To Website [Search Engine]"   → Resultados Google

Netblock:
  → "Netblock to IP Addresses"     → Lista de IPs del rango
  → "Shodan - Port Scan Netblock"  → Servicios abiertos

5. Domain → crt.sh → subdominios
6. Subdominios → resolver IPs
7. Domain → WHOIS → emails/personas
8. Emails → HIBP → brechas
9. Organizar con layout Organic
10. Exportar imagen + CSV para reporte
