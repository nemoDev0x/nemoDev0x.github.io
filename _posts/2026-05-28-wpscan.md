## WordPress como superficie de ataque

WordPress impulsa aproximadamente el 43% de todos los sitios web de internet. Esta cuota de mercado masiva lo convierte en el objetivo más frecuente en pentesting web, por una razón simple: la cantidad de instalaciones mal configuradas, con plugins desactualizados, o con credenciales por defecto es enorme.

La superficie de ataque de WordPress no es solo el core — que por sí solo tiene un historial de vulnerabilidades considerable — sino principalmente el ecosistema de plugins y temas. Hay más de 59.000 plugins en el repositorio oficial, y la mayoría son mantenidos por desarrolladores individuales con recursos limitados para mantener el código al día. Un plugin popular con una vulnerabilidad de SQL Injection o de carga de ficheros sin autenticar puede afectar a millones de sitios simultáneamente.

WPScan es el escáner de seguridad oficial para WordPress, desarrollado y mantenido por Automattic (la misma empresa detrás de WordPress.com). No es una herramienta genérica de fuzzing aplicada a WordPress — fue diseñada específicamente para este CMS y tiene una base de datos de vulnerabilidades propia (WPVulnDB) que se actualiza constantemente con CVEs específicos de WordPress, plugins y temas. Esta base de datos es lo que hace a WPScan indispensable: no solo descubre qué versión de un plugin tienes, sino que te dice directamente si esa versión tiene vulnerabilidades conocidas y te da el CVE.

## 1. Instalación y configuración

### Instalación

```bash
# En Kali Linux — viene preinstalado
wpscan --version

# Actualizar a la última versión
sudo gem update wpscan

# Instalar desde cero con gem (Ruby)
sudo gem install wpscan

# Con Docker (útil en sistemas sin Ruby)
docker pull wpscanteam/wpscan
docker run -it --rm wpscanteam/wpscan --url https://target.com

# Verificar instalación
wpscan --help
```

### Configurar la API key de WPVulnDB

WPScan sin API key hace enumeración básica pero no muestra las vulnerabilidades conocidas de cada plugin/tema detectado. La API key de WPVulnDB es gratuita para uso no comercial (hasta 75 requests al día) y es lo que transforma WPScan de un enumerador en un verdadero escáner de vulnerabilidades.

```bash
# Registrarse en https://wpscan.com/register
# Obtener la API key desde el perfil

# Usar la API key en cada comando
wpscan --url https://target.com --api-token TU_API_KEY_AQUI

# O configurarla en el fichero de configuración para no repetirla
mkdir -p ~/.wpscan
cat > ~/.wpscan/scan.yml << 'EOF'
cli_options:
  api_token: TU_API_KEY_AQUI
EOF

# Con el fichero de configuración, ya no hace falta el flag --api-token
wpscan --url https://target.com

# Verificar que la API key funciona
wpscan --api-token TU_API_KEY --url https://target.com --enumerate p --plugins-detection passive
```

### Actualizar la base de datos local

WPScan tiene una copia local de la base de datos de vulnerabilidades que se puede actualizar:

```bash
# Actualizar la base de datos de vulnerabilidades
wpscan --update

# Forzar actualización aunque la base de datos sea reciente
wpscan --update --force
```

## 2. Escaneo básico y reconocimiento inicial

Antes de enumerar plugins y usuarios, conviene hacer un reconocimiento inicial para confirmar que el objetivo es WordPress y obtener información sobre la configuración básica:

```bash
# Escaneo básico — confirmar WordPress y obtener info general
wpscan --url https://target.com

# Output incluye:
# - Versión de WordPress detectada
# - Tema activo
# - Si xmlrpc.php está habilitado
# - Si readme.html está accesible (revela versión exacta)
# - Si wp-cron.php está habilitado
# - Si registration está habilitada
# - Cabeceras de seguridad presentes/ausentes

# Escaneo con API key para obtener vulnerabilidades
wpscan --url https://target.com --api-token TU_KEY

# HTTPS con certificado autofirmado (labs, entornos de prueba)
wpscan --url https://target.com --disable-tls-checks

# Guardar resultados para el reporte
wpscan --url https://target.com --api-token TU_KEY -o reporte.txt
wpscan --url https://target.com --api-token TU_KEY -o reporte.json --format json

# Con proxy (para ver las peticiones en Burp Suite)
wpscan --url https://target.com --proxy http://127.0.0.1:8080

# Configurar User-Agent personalizado (para evadir WAF que bloquean WPScan)
wpscan --url https://target.com \
    --http-auth usuario:contraseña \
    --user-agent "Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36"
```

### Información que WPScan extrae sin enumerar

Incluso sin el flag `--enumerate`, WPScan extrae automáticamente:

```bash
# WPScan detecta automáticamente:
# 1. Versión de WordPress
#    → Desde el meta generator tag
#    → Desde el RSS feed (?feed=rss2)
#    → Desde el fichero readme.html
#    → Desde las versiones de ficheros JS/CSS en la cabecera

# 2. Tema activo y su versión
#    → Desde la URL del stylesheet (/wp-content/themes/nombre/style.css)

# 3. xmlrpc.php habilitado
#    → Vector de fuerza bruta y amplificación de peticiones
#    → Permite probar miles de contraseñas en una sola petición HTTP

# 4. readme.html accesible
#    → Revela la versión exacta de WordPress en texto claro

# 5. wp-cron.php accesible
#    → Puede usarse para DoS en algunos casos

# 6. Cabeceras de seguridad
#    → X-Frame-Options, X-Content-Type-Options, etc.
```

## 3. Enumeración de plugins

Los plugins son el vector de ataque más frecuente en WordPress. WPScan tiene tres modos de detección de plugins con diferente balance entre cobertura y sigilo:

### Modos de detección

```bash
# Modo pasivo (por defecto) — analiza el HTML de la página principal
# Solo detecta plugins que se cargan en la página principal
# No genera peticiones adicionales — completamente sigiloso
wpscan --url https://target.com --enumerate p --plugins-detection passive

# Modo agresivo — prueba activamente rutas de plugins conocidos
# Hace miles de peticiones HTTP adicionales
# Detecta plugins aunque no estén en la página principal
# Definitivamente visible en los logs del servidor
wpscan --url https://target.com --enumerate p --plugins-detection aggressive

# Modo mixto (por defecto cuando se especifica --enumerate p)
# Combina pasivo y algunas comprobaciones activas
wpscan --url https://target.com --enumerate p
```

### Enumerar plugins con vulnerabilidades

```bash
# Enumerar todos los plugins y mostrar sus vulnerabilidades
wpscan --url https://target.com \
    --enumerate p \
    --plugins-detection aggressive \
    --api-token TU_KEY

# El output para cada plugin tiene esta estructura:
# [+] Plugin: contact-form-7
#  | Location: https://target.com/wp-content/plugins/contact-form-7/
#  | Latest Version: 5.7.2
#  | Last Updated: 2023-01-15
#  |
#  | Found By: Urls In Homepage (Passive Detection)
#  |
#  | [!] 2 vulnerabilities identified:
#  |
#  | [!] Title: Contact Form 7 < 5.4 - Unrestricted File Upload
#  |     Fixed in: 5.4
#  |     References: https://wpscan.com/vulnerability/..., CVE-2020-35489

# Enumerar solo plugins vulnerables (más eficiente)
wpscan --url https://target.com \
    --enumerate vp \    # vp = vulnerable plugins
    --api-token TU_KEY

# Guardar solo los plugins vulnerables en JSON
wpscan --url https://target.com \
    --enumerate vp \
    --api-token TU_KEY \
    --format json \
    -o plugins_vulnerables.json
```

## 4. Enumeración de temas

Los temas también pueden contener vulnerabilidades — LFI, XSS, CSRF, e incluso RCE son comunes en temas premium mal auditados:

```bash
# Enumerar temas instalados
wpscan --url https://target.com --enumerate t

# Solo temas vulnerables
wpscan --url https://target.com --enumerate vt --api-token TU_KEY

    --enumerate t \

#  |     Title: Twenty Twenty-Three < 1.2 - XSS via ...
```

## 5. Enumeración de usuarios

La enumeración de usuarios es uno de los pasos más críticos en una auditoría de WordPress porque los usernames son la primera mitad de las credenciales. WordPress expone los usernames de varias formas por defecto:

```bash
# Enumerar usuarios — WPScan usa múltiples técnicas automáticamente
wpscan --url https://target.com --enumerate u

# Técnicas que usa WPScan para enumerar usuarios:
# 1. REST API: /wp-json/wp/v2/users
#    → Devuelve usuarios en JSON si la API está habilitada
# 2. Autor permalinks: /?author=1, /?author=2, ...
#    → Redirige a /author/username/ si el usuario existe
# 3. Login error messages:
#    → "Error: The username admin is not registered"
#    → Confirma o niega la existencia del usuario

# Especificar rango de IDs a probar (por defecto 1-10)
wpscan --url https://target.com --enumerate u --users-list 1-100

# Una vez tienes los usernames, el siguiente paso es fuerza bruta
# de contraseñas o password spraying
```

### Cómo protegerse (para el informe)

```bash
# Las técnicas que usa WPScan para enumerar usuarios son:

# 1. REST API — se puede deshabilitar con:
#    add_filter('rest_endpoints', function($endpoints) {
#        if (isset($endpoints['/wp/v2/users'])) {
#            unset($endpoints['/wp/v2/users']);
#        }
#        return $endpoints;
#    });

# 2. Autor permalinks — redirigir a 404 en lugar de /author/username/
#    Plugins como "Stop User Enumeration" lo hacen automáticamente

# 3. Mensajes de error de login — usar mensajes genéricos:
#    add_filter('login_errors', function() {
#        return 'Credenciales incorrectas.';
#    });
```

## 6. Fuerza bruta de contraseñas

Una vez tienes usernames válidos, WPScan puede hacer fuerza bruta o password spraying. Esta fase solo se ejecuta en engagements con autorización explícita para ello:

```bash
# Fuerza bruta de contraseña para un usuario específico
wpscan --url https://target.com \
    --usernames admin \
    --passwords /usr/share/seclists/Passwords/probable-v2-top1575.txt

# Fuerza bruta con lista de usuarios
wpscan --url https://target.com \
    --usernames usuarios.txt \
    --passwords passwords.txt

# Password spraying — probar una contraseña en todos los usuarios
# Mucho más seguro para evitar lockout de cuentas
wpscan --url https://target.com \
    --usernames usuarios.txt \
    --passwords one_password.txt \
    --password-attack wp-login  # Modo de ataque: wp-login o xmlrpc

# Usar xmlrpc para acelerar enormemente la fuerza bruta
# xmlrpc permite probar múltiples contraseñas en una sola petición
# si el sitio tiene xmlrpc.php habilitado
wpscan --url https://target.com \
    --usernames admin \
    --passwords wordlist.txt \
    --password-attack xmlrpc \
    --max-threads 5

# Controlar threads para no bloquear la cuenta o derribar el servidor
wpscan --url https://target.com \
    --usernames admin \
    --passwords wordlist.txt \
    --throttle 200    # Esperar 200ms entre peticiones
```

## 7. Enumeración completa — todas las opciones juntas

El flag `--enumerate` acepta múltiples parámetros combinados:

```bash
# Opciones de enumeración disponibles:
# u  → usuarios
# p  → plugins
# vp → plugins vulnerables solamente
# ap → todos los plugins (más lento pero más completo)
# t  → temas
# vt → temas vulnerables solamente
# at → todos los temas
# tt → timthumb (vulnerabilidad antigua pero aún relevante)
# cb → config backups (wp-config.php.bak, etc.)
# dbe → db exports (exportaciones de base de datos accesibles)
# m  → medios (ficheros subidos)

# Enumeración completa — lo que uso en auditorías reales
wpscan --url https://target.com \
    --enumerate u,vp,vt,cb,dbe \
    --plugins-detection aggressive \
    --themes-detection aggressive \
    --api-token TU_KEY \
    -o auditoria_completa.json \
    --format json

# Desglose de lo que hace esta enumeración:
# u   → usuarios del sitio
# vp  → plugins con vulnerabilidades conocidas
# vt  → temas con vulnerabilidades conocidas
# cb  → backups de wp-config.php accesibles (credenciales de DB)
# dbe → exportaciones de BD accesibles (.sql files)

# Versión más agresiva para cuando el tiempo no es factor
wpscan --url https://target.com \
    --enumerate u,ap,at,tt,cb,dbe,m \
    --plugins-detection aggressive \
    --themes-detection aggressive \
    --api-token TU_KEY \
    --disable-tls-checks \
    -o auditoria_exhaustiva.json \
    --format json
```

## 8. Interpretar y procesar los resultados

Los resultados de WPScan en formato JSON son muy ricos. Este script los procesa y genera un resumen ejecutivo:

```python
#!/usr/bin/env python3
"""
parse_wpscan.py — Procesa el output JSON de WPScan y genera resumen
Uso: python3 parse_wpscan.py auditoria.json
"""

import json
import sys

def parse_wpscan_json(filepath):
    with open(filepath) as f:
        data = json.load(f)

    print("=" * 60)
    print("  RESUMEN AUDITORÍA WORDPRESS")
    print("=" * 60)

    # Información general del sitio
    target = data.get("target_url", "Desconocido")
    print(f"\n[*] URL: {target}")

    # Versión de WordPress
    wp_version = data.get("version", {})
    if wp_version:
        ver_num = wp_version.get("number", "Desconocida")
        ver_status = wp_version.get("status", "")
        print(f"[*] WordPress: {ver_num} ({ver_status})")

        # Vulnerabilidades del core
        core_vulns = wp_version.get("vulnerabilities", [])
        if core_vulns:
            print(f"\n[!] VULNERABILIDADES DEL CORE ({len(core_vulns)}):")
            for v in core_vulns:
                title = v.get("title", "")
                fixed = v.get("fixed_in", "N/A")
                refs  = v.get("references", {})
                cve   = refs.get("cve", [""])[0] if refs.get("cve") else ""
                print(f"    [{cve}] {title}")
                print(f"    Corregido en: {fixed}")

    # Tema activo
    main_theme = data.get("main_theme", {})
    if main_theme:
        theme_name = main_theme.get("slug", "Desconocido")
        theme_ver  = main_theme.get("version", {}).get("number", "?")
        print(f"\n[*] Tema activo: {theme_name} v{theme_ver}")

        theme_vulns = main_theme.get("vulnerabilities", [])
        if theme_vulns:
            print(f"[!] VULNERABILIDADES DEL TEMA ({len(theme_vulns)}):")
            for v in theme_vulns:
                print(f"    {v.get('title', '')}")

    # Plugins con vulnerabilidades
    plugins = data.get("plugins", {})
    vuln_plugins = {k: v for k, v in plugins.items()
                    if v.get("vulnerabilities")}

    print(f"\n[*] Plugins detectados: {len(plugins)}")
    print(f"[!] Plugins con vulnerabilidades: {len(vuln_plugins)}")

    if vuln_plugins:
        print(f"\n{'─'*60}")
        print(f"  PLUGINS VULNERABLES — DETALLE")
        print(f"{'─'*60}")
        for slug, plugin in vuln_plugins.items():
            ver_num = plugin.get("version", {}).get("number", "?")
            vulns   = plugin.get("vulnerabilities", [])
            print(f"\n  [PLUGIN] {slug} v{ver_num}")
            for v in vulns:
                title     = v.get("title", "")
                fixed_in  = v.get("fixed_in", "No corregido")
                refs      = v.get("references", {})
                cve_list  = refs.get("cve", [])
                cvss      = v.get("cvss", {}).get("score", "N/A")
                vuln_type = v.get("type", "")

                print(f"    Título:   {title}")
                print(f"    Tipo:     {vuln_type}")
                print(f"    CVSS:     {cvss}")
                print(f"    Fix en:   {fixed_in}")
                if cve_list:
                    print(f"    CVEs:     {', '.join(cve_list)}")
                print()

    # Usuarios enumerados
    users = data.get("users", {})
    if users:
        print(f"\n[!] USUARIOS ENUMERADOS ({len(users)}):")
        for user_id, user_data in users.items():
            username = user_data.get("username", "?")
            print(f"    ID {user_id}: {username}")

    # Hallazgos interesantes (config backups, etc.)
    interesting = data.get("interesting_findings", [])
    critical_findings = [f for f in interesting
                         if f.get("type") in ["headers", "robots_txt", "xmlrpc",
                                              "readme", "registration"]]
    if critical_findings:
        print(f"\n[!] HALLAZGOS RELEVANTES:")
        for finding in critical_findings:
            ftype   = finding.get("type", "")
            url     = finding.get("url", "")
            entries = finding.get("interesting_entries", [])
            print(f"    [{ftype}] {url}")
            for entry in entries[:3]:
                print(f"    → {entry}")

    # Resumen de riesgo
    total_vulns = (len(core_vulns) if wp_version else 0) + \
                  sum(len(p.get("vulnerabilities", [])) for p in plugins.values())

    print(f"\n{'='*60}")
    print(f"  RESUMEN DE RIESGO")
    print(f"{'='*60}")
    print(f"  Vulnerabilidades totales: {total_vulns}")
    print(f"  Usuarios enumerados:      {len(users)}")
    xmlrpc = any(f.get("type") == "xmlrpc" for f in interesting)
    print(f"  XML-RPC habilitado:       {'SÍ — vector de fuerza bruta' if xmlrpc else 'NO'}")
    readme = any(f.get("type") == "readme" for f in interesting)
    print(f"  Readme.html accesible:    {'SÍ — revela versión exacta' if readme else 'NO'}")

if __name__ == "__main__":
    if len(sys.argv) < 2:
        print("Uso: python3 parse_wpscan.py <fichero.json>")
        sys.exit(1)
    parse_wpscan_json(sys.argv[1])
```

## 9. Flujo completo de auditoría WordPress

```bash
#!/bin/bash
# wp_audit.sh — Auditoría completa de WordPress
# Uso: ./wp_audit.sh https://target.com [api_token]

TARGET=$1
API_KEY=${2:-""}
OUTDIR="./wp_audit_$(echo $TARGET | sed 's|https\?://||;s|/|_|g;s|\.$||')"
mkdir -p "$OUTDIR"

if [ -z "$TARGET" ]; then
    echo "Uso: $0 <URL> [wpscan_api_token]"
    exit 1
fi

API_FLAG=""
[ -n "$API_KEY" ] && API_FLAG="--api-token $API_KEY"

echo "╔══════════════════════════════════════════╗"
echo "  Auditoría WordPress: $TARGET"
echo "╚══════════════════════════════════════════╝"

# ── FASE 1: RECONOCIMIENTO INICIAL ───────────────────────────────────
echo ""
echo "[1/4] Reconocimiento inicial y versión de WordPress..."
wpscan --url "$TARGET" \
    $API_FLAG \
    --disable-tls-checks \
    --format json \
    -o "$OUTDIR/01_basic.json" \
    --no-banner 2>/dev/null

# Extraer versión de WordPress
WP_VER=$(python3 -c "
import json
data = json.load(open('$OUTDIR/01_basic.json'))
ver = data.get('version', {}).get('number', 'Desconocida')
print(ver)
" 2>/dev/null)
echo "  WordPress versión: $WP_VER"

# ── FASE 2: ENUMERACIÓN DE USUARIOS ──────────────────────────────────
echo ""
echo "[2/4] Enumerando usuarios..."
wpscan --url "$TARGET" \
    $API_FLAG \
    --enumerate u \
    --disable-tls-checks \
    --format json \
    -o "$OUTDIR/02_users.json" \
    --no-banner 2>/dev/null

# Extraer usernames
python3 -c "
import json
data = json.load(open('$OUTDIR/02_users.json'))
users = data.get('users', {})
print(f'  Usuarios encontrados: {len(users)}')
for uid, udata in users.items():
    print(f'  → {udata.get(\"username\", \"?\")}')
" 2>/dev/null

# Guardar solo los usernames para fuerza bruta posterior
python3 -c "
import json
data = json.load(open('$OUTDIR/02_users.json'))
users = data.get('users', {})
with open('$OUTDIR/usernames.txt', 'w') as f:
    for uid, udata in users.items():
        f.write(udata.get('username', '') + '\n')
" 2>/dev/null

# ── FASE 3: ENUMERACIÓN DE PLUGINS Y TEMAS ───────────────────────────
echo ""
echo "[3/4] Enumerando plugins y temas vulnerables..."
wpscan --url "$TARGET" \
    $API_FLAG \
    --enumerate vp,vt,cb,dbe \
    --plugins-detection aggressive \
    --themes-detection aggressive \
    --disable-tls-checks \
    --format json \
    -o "$OUTDIR/03_vulns.json" \
    --no-banner 2>/dev/null

# Contar vulnerabilidades
python3 -c "
import json
data = json.load(open('$OUTDIR/03_vulns.json'))
plugins = data.get('plugins', {})
vuln_plugins = sum(1 for p in plugins.values() if p.get('vulnerabilities'))
total_plugin_vulns = sum(len(p.get('vulnerabilities', [])) for p in plugins.values())
print(f'  Plugins detectados: {len(plugins)}')
print(f'  Plugins vulnerables: {vuln_plugins}')
print(f'  Total vulns en plugins: {total_plugin_vulns}')

# Mostrar los más críticos
for slug, plugin in plugins.items():
    for v in plugin.get('vulnerabilities', []):
        cvss = v.get('cvss', {}).get('score', 0)
        if cvss and float(str(cvss)) >= 7.0:
            print(f'  [ALTO] {slug}: {v.get(\"title\", \"\")}')
" 2>/dev/null

# ── FASE 4: RESUMEN EJECUTIVO ─────────────────────────────────────────
echo ""
echo "[4/4] Generando resumen..."
python3 parse_wpscan.py "$OUTDIR/03_vulns.json" 2>/dev/null || true

echo ""
echo "╔══════════════════════════════════════════╗"
echo "  AUDITORÍA COMPLETADA"
echo "╠══════════════════════════════════════════╣"
printf "  %-28s %s\n" "WordPress:" "$WP_VER"
printf "  %-28s %s\n" "Usuarios:" "$(wc -l < $OUTDIR/usernames.txt 2>/dev/null || echo 0)"
echo "╠══════════════════════════════════════════╣"
echo "  Resultados en: $OUTDIR/"
echo "╚══════════════════════════════════════════╝"

# Recomendaciones automáticas
echo ""
echo "[*] Próximos pasos según hallazgos:"
[ -s "$OUTDIR/usernames.txt" ] && \
    echo "    → Usuarios encontrados: intentar password spraying"
echo "    → Revisar plugins vulnerables en $OUTDIR/03_vulns.json"
echo "    → Buscar exploits: searchsploit wordpress <plugin> <versión>"
```

## 10. Cheatsheet de referencia rápida

```bash
# ── INSTALACIÓN Y CONFIGURACIÓN ───────────────────────────────────────────
wpscan --update                                    # Actualizar base de datos
wpscan --version                                   # Ver versión instalada
# Configurar API key: ~/.wpscan/scan.yml → api_token: TU_KEY

# ── ESCANEO BÁSICO ────────────────────────────────────────────────────────
wpscan --url https://target.com                    # Sin API key
wpscan --url https://target.com --api-token KEY    # Con vulnerabilidades
```
