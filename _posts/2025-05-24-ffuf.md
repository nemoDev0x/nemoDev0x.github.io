## ffuf — cuando el fuzzing básico no es suficiente

Gobuster y Feroxbuster son excelentes para descubrir directorios y ficheros. Pero cuando necesitas fuzzear parámetros GET y POST, cabeceras HTTP, valores de cookies, subdominios, o cualquier parte de una petición HTTP con precisión quirúrgica, la herramienta de referencia es ffuf.

ffuf (Fuzz Faster U Fool) fue creado por Joona Hoikkala y se ha convertido en el estándar de la industria para fuzzing web avanzado. La razón de su popularidad está en su diseño: el placeholder `FUZZ` puede colocarse en cualquier parte de la petición HTTP — la URL, los parámetros, las cabeceras, el body, el valor de una cookie — y ffuf probará sistemáticamente cada entrada de la wordlist en esa posición. Esta flexibilidad lo hace útil en situaciones donde otras herramientas simplemente no llegan.

Lo que diferencia a ffuf en la práctica no es solo la capacidad de fuzzear cualquier parte de la petición, sino su sistema de filtrado. En fuzzing web el mayor problema no es encontrar respuestas — es distinguir las respuestas válidas del ruido. ffuf tiene filtros por código de respuesta, tamaño, número de palabras, número de líneas, tiempo de respuesta, y expresión regular, lo que permite afinar el output hasta dejar solo los hallazgos realmente interesantes.

## 1. Instalación y configuración

### Instalación

```bash
# En Kali Linux — viene preinstalado en versiones recientes
ffuf -V

# Instalar o actualizar con go (recomendado para tener la última versión)
go install github.com/ffuf/ffuf/v2@latest

# Verificar que está en el PATH
which ffuf
ffuf -V

# En macOS con Homebrew
brew install ffuf

# Binario precompilado desde GitHub Releases
wget https://github.com/ffuf/ffuf/releases/latest/download/ffuf_linux_amd64.tar.gz
tar -xzf ffuf_linux_amd64.tar.gz
sudo mv ffuf /usr/local/bin/
```

### Configuración global

ffuf lee un fichero de configuración en `~/.ffufrc` que permite establecer valores por defecto para no repetirlos en cada comando:

```bash
# Crear fichero de configuración con defaults útiles
cat > ~/.ffufrc << 'EOF'
# ffuf configuración global
# Estos valores se aplican a todos los comandos

# Threads por defecto
-t 50

# Ignorar errores SSL por defecto (útil en labs y CTFs)
-k

# Añadir salto de línea entre resultados para mayor legibilidad
-v

# Colores en el output
-c

# No mostrar el banner al inicio
-noninteractive
EOF
```

## 2. El placeholder FUZZ — concepto fundamental

Antes de entrar en ejemplos concretos, es fundamental entender cómo funciona ffuf. El placeholder `FUZZ` marca la posición en la petición HTTP donde se insertará cada entrada de la wordlist. ffuf construye una petición HTTP para cada entrada, la envía al servidor, y evalúa la respuesta según los filtros configurados.

```bash
# Ejemplo conceptual:
# Wordlist: admin, login, dashboard, api
# Comando: ffuf -u http://target/FUZZ -w wordlist.txt

# ffuf construye y envía estas peticiones:
# GET /admin HTTP/1.1
# GET /login HTTP/1.1
# GET /dashboard HTTP/1.1
# GET /api HTTP/1.1

# Y evalúa cada respuesta para determinar si es un hallazgo válido
```

### Múltiples placeholders

ffuf soporta múltiples placeholders simultáneos, cada uno asociado a una wordlist diferente:

```bash
# Dos placeholders — para combinaciones de usuario/contraseña
ffuf -u http://target/login \
    -X POST \
    -d "username=USER&password=PASS" \
    -w usuarios.txt:USER \
    -w passwords.txt:PASS \
    -H "Content-Type: application/x-www-form-urlencoded"

# Placeholder en URL y en cabecera al mismo tiempo
ffuf -u "http://target/FUZZ" \
    -H "X-Custom-Header: HEADER" \
    -w rutas.txt:FUZZ \
    -w cabeceras.txt:HEADER
```

## 3. Fuzzing de directorios y ficheros

Aunque Gobuster y Feroxbuster son más conocidos para esto, ffuf también hace un excelente trabajo con mayor flexibilidad de filtrado:

```bash
# Fuzzing básico de directorios
ffuf -u http://target/FUZZ \
    -w /usr/share/seclists/Discovery/Web-Content/directory-list-2.3-medium.txt

# Con extensiones — multiplicar la cobertura
# ffuf no tiene flag -x como Gobuster, se hace con wordlists que incluyen extensiones
# o con el flag -e que añade las extensiones automáticamente
ffuf -u http://target/FUZZ \
    -w /usr/share/seclists/Discovery/Web-Content/common.txt \
    -e .php,.html,.txt,.bak,.js,.json

# El flag -e en ffuf funciona diferente a -x en Gobuster:
# Con -e .php,.txt, ffuf prueba:
# admin → admin
# admin → admin.php
# admin → admin.txt
# login → login
# login → login.php
# etc.

# HTTPS con certificado autofirmado
ffuf -u https://target/FUZZ \
    -w wordlist.txt \
    -k

# Guardar resultados en diferentes formatos
ffuf -u http://target/FUZZ -w wordlist.txt -o resultados.json -of json
ffuf -u http://target/FUZZ -w wordlist.txt -o resultados.html -of html  # Reporte visual
ffuf -u http://target/FUZZ -w wordlist.txt -o resultados.csv  -of csv
```

### El problema del false positive — identificar y filtrar

El mayor desafío en fuzzing de directorios es que muchos servidores devuelven HTTP 200 para rutas que no existen, con una página de error personalizada. Si no filtras estas respuestas, obtienes miles de falsos positivos.

El proceso para manejar esto es siempre el mismo:

```bash
# PASO 1: Hacer una petición a una ruta que definitivamente no existe
# y medir las características de la respuesta de "no encontrado"
curl -s http://target/ruta-que-no-existe-xyz12345 -o /dev/null \
    -w "Código: %{http_code}\nTamaño: %{size_download}\n"
# Output:
# Código: 200
# Tamaño: 1823

# PASO 2: Filtrar respuestas de ese tamaño en ffuf
ffuf -u http://target/FUZZ \
    -w wordlist.txt \
    -fs 1823          # fs = filter size (filtrar por tamaño en bytes)

# OTRAS OPCIONES DE FILTRADO según la situación:
# -fc 404,403        → filter code (filtrar por código HTTP)
# -fw 45             → filter words (filtrar por número de palabras)
# -fl 12             → filter lines (filtrar por número de líneas)
# -ft 500            → filter time (filtrar respuestas > 500ms)
# -fr "Not Found"    → filter regex (filtrar si body contiene este patrón)

# MOSTRAR EN LUGAR DE FILTRAR (el opuesto):
# -mc 200,301        → match code (mostrar SOLO estos códigos)
# -ms 5000           → match size (mostrar SOLO respuestas de este tamaño)
# -mw 100            → match words (mostrar SOLO respuestas con este nº palabras)
# -mr "admin panel"  → match regex (mostrar SOLO si body contiene este patrón)
```

## 4. Fuzzing de parámetros — descubrir la superficie de ataque

Esta es la funcionalidad más diferenciadora de ffuf. Muchos endpoints web aceptan parámetros que no están documentados — parámetros de debug, parámetros de administración, parámetros de configuración que quedaron en producción por error. ffuf permite descubrirlos sistemáticamente.

### Fuzzing de parámetros GET

```bash
# Descubrir qué parámetros acepta un endpoint
# La URL tiene FUZZ en la posición del nombre del parámetro
ffuf -u "http://target/search?FUZZ=test" \
    -w /usr/share/seclists/Discovery/Web-Content/burp-parameter-names.txt \
    -fs 1823    # Filtrar la respuesta base (sin parámetro o con parámetro inválido)

# Cuando encuentres un parámetro válido, fuzzear sus valores
# Por ejemplo, si descubres el parámetro "id":
ffuf -u "http://target/user?id=FUZZ" \
    -w /usr/share/seclists/Fuzzing/Integers.txt \
    -mc 200 \
    -fs 0    # Filtrar respuestas vacías

# Fuzzing de valores de tipo texto (para LFI, SSRF, etc.)
ffuf -u "http://target/page?file=FUZZ" \
    -w /usr/share/seclists/Fuzzing/LFI/LFI-Jhaddix.txt \
    -mc 200 \
    -fs 1823

# Identificar parámetros que aceptan URLs (SSRF)
ffuf -u "http://target/fetch?url=FUZZ" \
    -w /usr/share/seclists/SSRF/cloud-metadata.txt \
    -mc 200 \
    -fs 1823
```

### Fuzzing de parámetros POST

```bash
# Descubrir parámetros en formularios POST
ffuf -u http://target/api/endpoint \
    -X POST \
    -H "Content-Type: application/x-www-form-urlencoded" \
    -d "FUZZ=test" \
    -w /usr/share/seclists/Discovery/Web-Content/burp-parameter-names.txt \
    -fs 1823

# Para APIs que usan JSON
ffuf -u http://target/api/user \
    -X POST \
    -H "Content-Type: application/json" \
    -d '{"FUZZ":"test"}' \
    -w /usr/share/seclists/Discovery/Web-Content/burp-parameter-names.txt \
    -fs 1823

# Caso más complejo: fuzzear el valor de un campo JSON conocido
ffuf -u http://target/api/login \
    -X POST \
    -H "Content-Type: application/json" \
    -d '{"username":"admin","password":"FUZZ"}' \
    -w /usr/share/seclists/Passwords/probable-v2-top1575.txt \
    -fs 1823    # Tamaño de la respuesta de "credenciales incorrectas"

# Encontrar parámetros ocultos en una API REST
# Muchas APIs tienen parámetros de debug o admin no documentados
ffuf -u "http://target/api/users?FUZZ=1" \
    -w /usr/share/seclists/Discovery/Web-Content/burp-parameter-names.txt \
    -fw 1       # Filtrar respuestas con solo 1 palabra (error JSON mínimo)
```

### Fuzzing de IDs — IDOR (Insecure Direct Object Reference)

Una de las vulnerabilidades más comunes en APIs es el IDOR: acceder a recursos de otros usuarios simplemente cambiando un ID numérico en la petición. ffuf automatiza la verificación:

```bash
# Fuzzear IDs numéricos para detectar IDOR
# Generar una wordlist de números del 1 al 1000
seq 1 1000 > ids_1_1000.txt

ffuf -u "http://target/api/user/FUZZ" \
    -w ids_1_1000.txt \
    -mc 200 \
    -t 30    # Threads moderados para no saturar la API

# Si la respuesta para tu propio usuario tiene un tamaño específico,
# buscar otros usuarios con el mismo tamaño de respuesta
ffuf -u "http://target/api/user/FUZZ" \
    -w ids_1_1000.txt \
    -ms 847   # Tamaño de una respuesta válida de perfil de usuario

# Fuzzear con cookie de autenticación para acceder a recursos autenticados
ffuf -u "http://target/api/document/FUZZ" \
    -w ids_1_1000.txt \
    -H "Cookie: session=tu_session_token_aqui" \
    -mc 200 \
    -t 30
```

## 5. Fuzzing de cabeceras HTTP

Las cabeceras HTTP son una superficie de ataque frecuentemente ignorada. Los servidores web y las aplicaciones procesan docenas de cabeceras, algunas de las cuales pueden activar comportamientos especiales: cabeceras de debug, cabeceras de bypass de autenticación, cabeceras de proxy interno.

```bash
# Descubrir cabeceras que producen comportamiento diferente
# Muy útil para encontrar bypasses de autenticación y debug modes
ffuf -u http://target/ \
    -H "FUZZ: test" \
    -w /usr/share/seclists/Discovery/Web-Content/BurpSuite-ParamMiner/uppercase-headers.txt \
    -fs 1823

# Fuzzear el VALOR de una cabecera conocida
# Por ejemplo, buscar valores del header X-Forwarded-For que cambian el comportamiento
ffuf -u http://target/admin \
    -H "X-Forwarded-For: FUZZ" \
    -w /usr/share/seclists/Fuzzing/IP-Addresses.txt \
    -mc 200

# Buscar cabeceras que hacen bypass de restricciones de IP
# Algunos servidores confían en X-Forwarded-For, X-Real-IP, etc.
ffuf -u http://target/admin \
    -H "FUZZ: 127.0.0.1" \
    -w cabeceras_ip_bypass.txt \
    -mc 200,301,302

# Crear wordlist de cabeceras comunes de bypass de IP
cat > cabeceras_ip_bypass.txt << 'EOF'
X-Forwarded-For
X-Real-IP
X-Originating-IP
X-Remote-IP
X-Remote-Addr
X-Client-IP
X-Host
X-Custom-IP-Authorization
True-Client-IP
CF-Connecting-IP
Forwarded
X-ProxyUser-Ip
X-Original-URL
X-Rewrite-URL
X-Forwarded-Host
X-Forwarded-Proto
X-Override-URL
EOF

# Buscar cabeceras de debug que revelan información interna
ffuf -u http://target/ \
    -H "FUZZ: true" \
    -w cabeceras_debug.txt \
    -fr "404|not found"    # Filtrar respuestas de error

cat > cabeceras_debug.txt << 'EOF'
X-Debug
X-Debug-Mode
Debug
X-Dev-Mode
X-Development
X-Test
X-Internal
X-Admin
X-Original-URL
X-Rewrite-URL
EOF
```

## 6. Fuzzing de subdominios y virtual hosts

ffuf puede hacer fuzzing de subdominios modificando la cabecera `Host` en cada petición, lo que descubre virtual hosts que comparten la misma IP:

```bash
# Virtual host fuzzing — modificar la cabecera Host
# FUZZ se reemplaza por cada subdominio de la wordlist
ffuf -u http://10.10.10.10 \
    -H "Host: FUZZ.example.com" \
    -w /usr/share/seclists/Discovery/DNS/subdomains-top1million-5000.txt \
    -fs 1823    # Filtrar la respuesta por defecto (sin vhost coincidente)

# El flujo de trabajo para virtual hosts:
# 1. Primero identificar la respuesta base (sin Host header válido)
curl -s -H "Host: nonexistent.example.com" http://10.10.10.10 | wc -c
# Output: 1823 → ese es el tamaño a filtrar

# 2. Fuzzear filtrando ese tamaño
ffuf -u http://10.10.10.10 \
    -H "Host: FUZZ.example.com" \
    -w /usr/share/seclists/Discovery/DNS/subdomains-top1million-5000.txt \
    -fs 1823 \
    -t 50

# 3. Añadir los subdominios encontrados al /etc/hosts para acceder a ellos
echo "10.10.10.10  dev.example.com staging.example.com" >> /etc/hosts

# Fuzzing de subdominios DNS (diferente — hace resolución DNS real)
# ffuf en modo subdominio DNS — fuzz en el hostname completo
ffuf -u http://FUZZ.example.com \
    -w /usr/share/seclists/Discovery/DNS/subdomains-top1million-5000.txt \
    -fs 0 \
    -t 50
```

## 7. Fuzzing de autenticación

ffuf es muy efectivo para probar credenciales en formularios de login, especialmente cuando el formulario tiene protecciones básicas que otras herramientas no manejan bien:

```bash
# Brute force de login básico — HTTP form POST
# PASO 1: Identificar el tamaño de la respuesta de login fallido
curl -s -X POST http://target/login \
    -d "username=admin&password=wrongpassword" | wc -c
# Output: 1347

# PASO 2: Fuzzear la contraseña filtrando el tamaño del fallo
ffuf -u http://target/login \
    -X POST \
    -d "username=admin&password=FUZZ" \
    -H "Content-Type: application/x-www-form-urlencoded" \
    -w /usr/share/seclists/Passwords/probable-v2-top1575.txt \
    -fs 1347    # Filtrar respuesta de login fallido
    # Cualquier respuesta de tamaño diferente es potencialmente un login exitoso

# Password spraying — probar una sola contraseña en muchos usuarios
# (evita bloqueo de cuentas)
ffuf -u http://target/login \
    -X POST \
    -d "username=FUZZ&password=Password1!" \
    -H "Content-Type: application/x-www-form-urlencoded" \
    -w usuarios.txt \
    -fs 1347 \
    -t 5    # Threads bajos para no activar rate limiting

# Login con token CSRF — muchos formularios modernos requieren un token
# que cambia con cada petición. Para esto hay que usar Burp Suite en combinación
# o un script personalizado. ffuf solo es efectivo cuando el CSRF token
# no cambia entre peticiones o cuando no hay CSRF protection.

# Identificar si hay rate limiting
ffuf -u http://target/login \
    -X POST \
    -d "username=admin&password=FUZZ" \
    -H "Content-Type: application/x-www-form-urlencoded" \
    -w /usr/share/seclists/Passwords/probable-v2-top1575.txt \
    -fs 1347 \
    -rate 2    # -rate limita a N peticiones por segundo — para evadir rate limiting
```

## 8. Técnicas avanzadas

### Usar ffuf con Burp Suite como proxy

Pasar el tráfico de ffuf por Burp Suite permite ver y modificar cada petición, añadir cabeceras de autenticación de forma visual, y analizar las respuestas en detalle:

```bash
# Primero iniciar Burp Suite con el proxy en 127.0.0.1:8080

# Enviar tráfico de ffuf por Burp
ffuf -u http://target/FUZZ \
    -w wordlist.txt \
    -x http://127.0.0.1:8080    # Proxy HTTP
    -k    # Importante: -k para ignorar el certificado SSL de Burp

# Para HTTPS
ffuf -u https://target/FUZZ \
    -w wordlist.txt \
    -x http://127.0.0.1:8080 \
    -k
```

### Modo recursivo en ffuf

ffuf tiene soporte básico de recursión que se activa con `-recursion`:

```bash
# Recursión automática hasta profundidad 3
ffuf -u http://target/FUZZ \
    -w wordlist.txt \
    -recursion \
    -recursion-depth 3 \
    -e .php,.html \
    -fc 404

# La recursión en ffuf es más básica que en Feroxbuster
# Para recursión avanzada, usar Feroxbuster
```

### Guardar y reanudar escaneos

```bash
# Guardar el estado del escaneo para poder reanudarlo
ffuf -u http://target/FUZZ \
    -w wordlist.txt \
    -o estado.json \
    -of json

# ffuf también tiene modo interactivo — durante el escaneo puedes:
# p → pausar/reanudar
# q → guardar y salir
# En modo interactivo (default) puedes cambiar filtros en tiempo real
```

### Script de reconocimiento web con ffuf

```python
#!/usr/bin/env python3
"""
ffuf_recon.py — Reconocimiento web automatizado con ffuf
Ejecuta múltiples fases de fuzzing y consolida los hallazgos
"""

import subprocess
import json
import os
import sys

def run_ffuf(cmd, output_file):
    """Ejecuta un comando ffuf y devuelve los resultados del JSON."""
    full_cmd = cmd + ["-o", output_file, "-of", "json", "-s"]
    try:
        subprocess.run(full_cmd, capture_output=True, timeout=300)
        if os.path.exists(output_file):
            with open(output_file) as f:
                data = json.load(f)
                return data.get("results", [])
    except Exception as e:
        print(f"  [-] Error: {e}")
    return []

def get_baseline_size(url):
    """
    Obtiene el tamaño de la respuesta para una ruta que no existe.
    Este tamaño se usa para filtrar falsos positivos.
    """
    result = subprocess.run(
        ["curl", "-s", "-k", f"{url}/ffuf-nonexistent-path-xyz123",
         "-o", "/dev/null", "-w", "%{size_download}"],
        capture_output=True, text=True
    )
    try:
        return int(result.stdout.strip())
    except:
        return 0

def web_recon(target_url, output_dir):
    os.makedirs(output_dir, exist_ok=True)

    print(f"\n[*] Objetivo: {target_url}")
    print(f"[*] Detectando tamaño baseline para filtrado...")
    baseline = get_baseline_size(target_url)
    print(f"[*] Baseline: {baseline} bytes — se filtrarán respuestas de este tamaño")

    all_findings = []

    # ── FASE 1: Directorios comunes ───────────────────────────────────
    print(f"\n[1/4] Fuzzing de directorios...")
    results = run_ffuf(
        ["ffuf", "-u", f"{target_url}/FUZZ", "-k",
         "-w", "/usr/share/seclists/Discovery/Web-Content/common.txt",
         "-e", ".php,.html,.txt,.bak,.js",
         "-t", "50", "-fs", str(baseline)],
        f"{output_dir}/01_dirs.json"
    )
    print(f"  [+] Encontrados: {len(results)}")
    all_findings.extend([{"phase": "dirs", **r} for r in results])

    # ── FASE 2: Parámetros GET ────────────────────────────────────────
    print(f"\n[2/4] Fuzzing de parámetros GET...")
    results = run_ffuf(
        ["ffuf", "-u", f"{target_url}/?FUZZ=test", "-k",
         "-w", "/usr/share/seclists/Discovery/Web-Content/burp-parameter-names.txt",
         "-t", "40", "-fs", str(baseline)],
        f"{output_dir}/02_params.json"
    )
    print(f"  [+] Encontrados: {len(results)}")
    all_findings.extend([{"phase": "params", **r} for r in results])

    # ── FASE 3: Virtual hosts ─────────────────────────────────────────
    print(f"\n[3/4] Fuzzing de virtual hosts...")
    domain = target_url.replace("https://", "").replace("http://", "").split("/")[0]
    results = run_ffuf(
        ["ffuf", "-u", target_url, "-k",
         "-H", f"Host: FUZZ.{domain}",
         "-w", "/usr/share/seclists/Discovery/DNS/subdomains-top1million-5000.txt",
         "-t", "50", "-fs", str(baseline)],
        f"{output_dir}/03_vhosts.json"
    )
    print(f"  [+] Encontrados: {len(results)}")
    all_findings.extend([{"phase": "vhosts", **r} for r in results])

    # ── FASE 4: Cabeceras de bypass ───────────────────────────────────
    print(f"\n[4/4] Probando cabeceras de bypass...")
    bypass_headers = [
        "X-Forwarded-For", "X-Real-IP", "X-Client-IP",
        "X-Originating-IP", "X-Override-URL", "X-Rewrite-URL"
    ]
    bypass_file = f"{output_dir}/bypass_headers.txt"
    with open(bypass_file, "w") as f:
        for h in bypass_headers:
            f.write(h + "\n")

    results = run_ffuf(
        ["ffuf", "-u", f"{target_url}/admin", "-k",
         "-H", "FUZZ: 127.0.0.1",
         "-w", bypass_file,
         "-mc", "200,301,302"],
        f"{output_dir}/04_bypass.json"
    )
    print(f"  [+] Posibles bypasses: {len(results)}")
    all_findings.extend([{"phase": "bypass", **r} for r in results])

    # ── RESUMEN ───────────────────────────────────────────────────────
    print(f"\n{'='*55}")
    print(f"  RECONOCIMIENTO COMPLETADO")
    print(f"{'='*55}")
    print(f"  Total hallazgos: {len(all_findings)}")
    print(f"\n  DETALLE:")
    for finding in sorted(all_findings, key=lambda x: x.get("status", 0)):
        url   = finding.get("url", "")
        code  = finding.get("status", "?")
        size  = finding.get("length", "?")
        words = finding.get("words", "?")
        phase = finding.get("phase", "?")
        print(f"  [{code}] {url} | {size}B | {words}w | ({phase})")

    # Guardar consolidado
    with open(f"{output_dir}/all_findings.json", "w") as f:
        json.dump(all_findings, f, indent=2)
    print(f"\n  Resultados en: {output_dir}/")

if __name__ == "__main__":
    if len(sys.argv) < 2:
        print("Uso: python3 ffuf_recon.py <URL>")
        sys.exit(1)
    web_recon(sys.argv[1], "./ffuf_recon_output")
```

## 9. Cheatsheet de referencia rápida

```bash
# ── FUZZING DE DIRECTORIOS ────────────────────────────────────────────────
```
